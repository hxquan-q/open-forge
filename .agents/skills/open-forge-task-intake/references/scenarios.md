# 统一入口的路由验收场景

这是行为评估清单，不是字符串匹配分类器。改动路由后逐项核对；只有实际在新会话/已授权模型中执行并记录输入、行为和结果，才能称为模型路由评测通过。静态脚本只能检查镜像与相对文件链接，不检查自然语言执行质量。

| 输入/上下文 | 应选择的行为 | 不允许的捷径 |
|---|---|---|
| 给列表加过滤，保留当前排序 | 定位用户入口，薄切片，组件/流程与条件测试 | 要用户提供文件清单；只测过滤纯函数 |
| 点击取消还在执行工具 | 诊断生命周期，先复现，取消/副作用回归 | 只隐藏加载动画；真实 Provider 默认试验 |
| 只重构这个模块，功能不变 | 不变量与现有基线，公开接口行为保持 | 必须制造失败测试；顺便改协议 |
| 给保存流程补 TDD | 确认现有保存合同，每片 red/green，覆盖连续操作 | 每个内部函数都让用户批准；一次写完所有测试 |
| CI Windows 安装失败 | 读取实际 workflow/log/脚本，平台诊断与回归 | 换 npm；去掉 Windows 矩阵 |
| CI 太慢，优化缓存 | 测量关键路径、缓存输入和失效条件 | 不测就并行一切；跳过测试 |
| 准备自动发布流水线 | 配置/产物/权限合同与授权闸门 | 顺便 push tag 或触发发布 |
| AI 说文件生成了但实际没有 | 工具/产物事实合同与模型质量分开定位 | Mock 返回成功就宣称真实模型通过 |
| AI 摘要不够准确 | 代表性资料与合格标准，区分确定断言和判断式评估 | 用完全一致措辞断言；未授权收费调用 |
| 页面视觉间距调整 | 现有设计规范；无行为变化时核对样式和约束 | 默认启动 verify:ui 或真实用户实例 |
| Expo 页面导航调整 | 先 expo-overview，再框架对应测试路线 | 套用 Desktop DOM 测试 |
| Go 网关连接泄漏 | 包级 README、Go 测试/资源基线 | 根 TypeScript check 当作 Go 验证 |
| 只研究这两个方案 | 只读证据与取舍记录 | 创建实现或运行发布 |
| 需求已实现但用户说不符合预期 | verifying，反馈归因→复现→修正→重新验收 | 用户未确认却自动 done |
| 正常测试通过但完整检查有既有失败 | 记录归属和证据，报告未满足门禁，不夹带修复 | 禁用检查；冒称整体验证通过 |
| 两个互不依赖功能且明确授权多 Agent | 评估写范围、独立 Worktree、集成后验证 | 共享主目录并行写；扩大 push 权限 |

本次维护的验收记录写入关联 Task，区分文档场景审查、机械回归和实际模型试跑；三者不得混称。
