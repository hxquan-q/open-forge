# Open Forge 用户文案约定

本文约定本项目 README、公开文档和客户端说明的写法。文案先说明用户能完成的工作，再给出操作、前提和可核对的结果。产品称呼与当前品牌配置保持一致。

## 名称和范围

| 场景 | 写法 |
| --- | --- |
| 仓库、工程手册与项目文档 | Open Forge |
| 默认桌面分发档 | 中文小爱ai，英文 Allstr ai |
| 显式 self 档 | Open Forge |
| Desktop 界面 | 使用 i18n 和宿主品牌层，遵循实际构建 |
| 技术示例 | 使用当前包名、命令、字段和文件格式原名 |

不要把兼容包名、协议或目录改成没有对应实现的新名称。品牌档位和 lite/full 是两个独立选择，配置细节见[构建模式](desktop/build-modes.md)。

## 描述已经存在的行为

- 以源码、公开导出、Schema、测试和已发布资产为依据。开发中、待验收和已发布分别说明。
- 说明功能入口、必要配置、权限及平台条件；示例展示用户最后会看到的结果。
- 模型、MCP、插件和云服务的网络边界按实际实现说明，不笼统承诺全部离线或数据从不外发。
- 安装平台以具体 Release 资产为准；源码可构建不等于存在可下载安装包。
- Full 云功能只有在兼容服务端已配置时可用，不将账号、订阅或托管市场写成默认前置。
- 仓库首页只介绍本项目，不沿用其他项目的社区背书、愿景、商业计划或部署状态。

## 操作、状态与恢复

操作文字使用清晰动词，例如「连接主机」「保存模型」「重新加载插件」。同一个动作在界面和手册中使用一致称呼。

状态说明回答发生了什么、结果是否保存以及用户下一步可以做什么。用户取消、执行失败、网络断开和权限不足分别表达；没有实际重试时不写「正在重试」。

示例：

- 「连接失败，请检查主机地址和 SSH 配置后重试。」
- 「文件传输已取消，已完成的文件保留在目标目录。」仅在实际行为如此时使用。
- 「模型配置已保存。」与「模型连接测试通过。」分别对应保存结果和测试结果。

公开文档保持可操作，不把内部模块名、Task 状态或调试细节塞进普通用户流程。需要诊断信息时链接到参考手册。

## 中英文与界面接线

公开文档中文和 `en/` 镜像同步维护，保留相同路径及操作含义。命令、配置键和协议示例不翻译。页面标题、摘要、图片说明、按钮与可访问性文本都属于文案范围。

Desktop 的 title、aria、placeholder 和菜单文字走既有 i18n；不要通过硬编码名称绕过品牌层。帮助文档可以按功能描述入口，具体标签以所用版本和品牌档为准。

## 更新前核对

核对来源事实、读者任务、当前品牌、成功与失败结果、双语含义、链接和命令。涉及行为变化时同步用户指南与验证；文案调整不应改变协议、权限或运行时语义。
