# ADR-0156：桌面侧栏工作空间分组沿用项目与会话存储

## 状态

已接受（2026-11-26，PLAN-0032 D5 拍板结果落地；参照上游 ADR-0155《desktop-workspaces》重写——上游原编号 0155 与本地 ADR-0155《自动化运行会话策略与调度数据模型 v2》同号不同题，本 ADR 取本地新编号）

## 背景

侧栏里的项目和会话越来越多时，无法按工作内容分开整理。上游 `d6f9906c4` 引入本机工作空间分组：每个项目或独立会话归属唯一空间，`ctrl+1..9` 切换，空间状态存 Renderer 版本化本地配置，物理目录和会话数据不变。

本地与上游的结构性差异决定不能照抄：

- 本地有 **Work/Coding 工作区模式**（`domains/workspace-mode`）与 **Allstar 版块**两册，上游没有；团队会话按 `16e40c8e6` 进入 Allstar 版块，上游则按 Team ID 归属工作空间。
- 本地侧栏底栏、设置菜单、命令菜单均经本地重做（`SettingsMenuPopover` 等上游文件在本地已不存在或形态不同），交互挂载点需要重新设计适配。
- 术语冲突：上游「工作空间」（workspace）在本地 zh 文案里已用于团队会话上下文（`chat.json` `teamNewWorkspaceContext`）与插件「工作区视图」能力面。PLAN-0032 D5 要求命名统一先行。

PLAN-0032 D5 已拍板：**工作空间只作用于普通册（非 Allstar、非团队）；Allstar 不纳入工作空间分组；团队会话保持本地 Allstar 版块归属，不按上游 Team ID 归属**。

## 决策

### 1. 空间是本机侧栏的分组，不动身份与物理存储

工作空间是本机侧栏的分组。Renderer 在版本化的本地配置（`atomWithStorage` + `localStorage`，键 `vetta.desktop-spaces.v1`）中保存自定义空间、顺序、选中空间、单一归属和每个空间最近打开的项目或会话。项目按注册路径归属，独立普通会话按会话路径归属。缺少明确归属的数据回落到主空间，因此既有数据无需迁移。项目内的会话根据项目推导归属。

移动磁盘目录或改变会话身份会影响桌面端、远程访问及自动化的共同入口，因此**归属记录只存在于 Renderer 本地配置**，项目和会话的磁盘位置、`.vetta` 状态目录、调度与自动化引用全部不变。

### 2. 归属范围收窄：普通册 only，无 team 归属维度

与上游的三类归属（project / conversation / team）不同，本地归属只有两类：项目按注册路径、独立普通会话按会话路径。团队会话保持 Allstar 版块归属，不进入空间归属记录；Allstar 版块的项目与会话不被空间过滤。相应地：

- `SpaceLocation` 不保留上游的 `team` 分支；空间切换恢复「最近打开」只处理 project / conversation 两种。
- 侧栏过滤只作用于普通册的项目与会话列表；Allstar 版块各行不受选中空间影响。

### 3. 交互形态：底栏切换器 + 快捷键 + 设置页管理

- 侧栏底部用按钮组（`@vetta-org/ui` ButtonGroup，已就绪）承载工作空间切换，支持 Ctrl+1 到 Ctrl+9（进入可配置 keybinding 注册表，遵守「快捷键进入可配置 keybinding」硬边界），超出部分收进「更多」弹层，菜单底部直达工作空间设置。
- 设置页新增工作空间标签页：创建、重命名、拖动排序、移除空间；新建/编辑对话框提供图标选择（上游 60 个 solar 线性图标集合照移，主空间专用 `home` 不在可选列表）。
- 切换空间恢复该空间上次打开的内容（`locations` 记录），并为每个空间保留独立的会话草稿（`session-input-draft` 键加空间维度）。
- 项目与独立会话的右键菜单提供「移动到工作空间」子菜单；全局搜索结果标注所属空间，激活时先切到对应空间。

### 4. 移除路径：两档确认，主进程核验

- 移除空间默认把项目与会话并回主空间（仅清除归属记录）。
- 用户确认同时移除内容时，桌面通过**已有的**项目和会话服务分别处理；主进程核验独立会话的类型和运行状态（运行中的会话阻止删除），专属目录按现有会话工作目录规则处理，共享目录和项目会话保留。这需要在会话删除 IPC 上新增仅限工作空间移除使用的删除模式，不复用通用删除入口。
- 遇到部分失败时用户可重试剩余内容，空间本身在全部内容处理完毕后移除。

### 5. 命名与文案

界面文案跟随上游用「工作空间」指称本功能。与既有用法的边界：插件能力面的「工作区视图」（workspaceView）是整页视图 slot、团队会话的「新工作空间」是团队上下文——两者均不出现在侧栏分组语境，文案审校时确保不与分组功能混淆，不改动这两个既有词条。

## 备选方案

- **完全跟随上游（team 按 Team ID 归属）**：与本地 Allstar 版块语义冲突，团队会话归属需迁移，用户已习惯的入口会变。D5 已否决。
- **把空间注册表并入主进程项目配置**：统一多窗口写入并为远程端提供可同步合同。但第一版入口和归属都是桌面本地的，沿用 Renderer 本地存储和 storage 事件即可共享配置，也避免把空间概念扩展到移动端、IM 和自动化协议。若将来要跨设备同步，可读取当前配置后迁移归属记录，项目和会话身份不受影响。
- **不引入工作空间**：放弃 `ctrl+1..9` 快速切换与分组整理价值。D5 已否决。

## 后果

- 全局搜索继续读取所有空间的项目和会话，打开时才切换空间。
- 归档项目保留归属，空间消失后回到主空间。
- 新增持久化（`vetta.desktop-spaces.v1`）为先写先赢的本地配置：删除该键即完全回滚，不依赖改写用户数据（符合 PLAN-0032 的持久化回退原则）。
- 空间是 Renderer 本地状态，多窗口靠 storage 事件同步，存在极端情况下的末写覆盖窗口；这与既有 Renderer 本地配置（草稿、面板布局）同一等级，可接受。
- `session-input-draft` 的存储键加入空间维度属于持久化格式演进：旧键内容按主空间读取，无需迁移。
