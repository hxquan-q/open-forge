# 共享资源准入与调用结果、底层释放分离

## 状态

Accepted（2026-10-28）

## 背景

Pi 的 codemode 准入修复说明容量不足可以是可取消、有期限的等待，取消结果完成却不能证明 worker 已退出。
本仓已有子代理 FIFO、工具窗口和共享 OCR gate，无需新建 Agent Runtime；但旧 gate 的排队不能取消、没有
边界或可归因观测。用户在 RESEARCH-0047 后授权 PLAN-0026 / TASK-0410–0411 实施。

## 决策

- `runtime-tools` 扩展现有 `AsyncExecutionGate`，保持 `run(operation)` 和默认 FIFO 兼容，额外参数提供
  等待取消、等待期限、队列长度预算、稳定身份与安全观察回调。可选 owner 轮转保持组内 FIFO，不抢占在途操作。
- 调用方取消可以先返回；容量仍由原始操作 Promise 持有，直到其收敛才释放。同步抛错、异步拒绝和启动失败
  同样归还容量。操作 Promise 应代表宿主资源的真实生命周期，gate 不伪造进程/worker 退出证明。
- 观察回调不改变业务结果；事件不含正文、路径、参数、返回值或原始取消原因。等待失败以稳定错误 code 分类，
  不自动重放工具。通用 gate 默认无新的等待预算，以保护既有知识库调用方。
- Coding Agent 产品层选择 OCR 的共享策略：原并发（默认 1）、最多 8 个等待者、最多 60 秒等待与 session
  轮转。8 对齐现有 workflow 单批规模，是显式过载边界；60 秒为准入体验预算，不替代图像 5 分钟/PDF 30 分钟
  执行时限。Node 工具传入宿主 session/tool-call 身份和取消信号，进程生命周期仍归平台 Adapter。
- OCR 共享的是调度状态；每个 session 的观察 publisher 由局部包装器持有，避免第一位调用者的身份污染其他
  session。产品默认值、环境实现与通用协议继续遵循 ADR-0077。
- 子代理逻辑调度槽继续遵循 BUG-0001 的有界收尾；其 settled 不等于物理资源退出。TASK-0411 通过纯 callback
  发布准入/释放事实，保持 ADR-0087 的零 workspace 依赖与产品观察接线边界。

## 备选方案

统一所有 Agent/Tool 的全局信号量会混淆资源类型，且可能让父执行持有名额等待同池子任务；不采用。直接在取消
结果返回时归还资源会超发；无限等资源退出又会破坏子代理有界收尾。新建框架或引入 codemode 超出当前产品需求。
对所有旧 gate 默认启用轮转/有限排队会改变既有调用方，因此只由 OCR 产品策略显式选入。

## 后果与迁移

无持久化或工具 Schema 迁移，旧 gate/测试替身无需新增必需方法。OCR 过载可能得到明确队满/等待超时，调用方
应等待容量恢复后发起新操作，不盲目重试。需要真实物理退出信号的未来资源应在 Host Port 提供可验证生命周期，
不能仅套用调用方 Promise。软件回归覆盖等待、取消、资源收敛、轮转与隐私；未据此声称真实模型吞吐改善。
