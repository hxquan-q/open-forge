# ADR-0151：Allstar 自主开发版块——独立项目册、同路径双册登记与按模式标签的可见性

## 状态

已接受（2026-10-27，M1-1 用户评审通过）

## 背景

M0（c5700985d）把「代码」对话模式收进侧边栏「Allstar自主开发」版块入口。M1 要把
版块做成有专属路由、项目空间与会话列表的完整版块（0.1.4），需先定三个模型问题：
版块项目与宿主项目注册表的关系；开发/对话会话的隔离与互见；存量数据的去向。

用户四项裁定：
1. 版块项目与普通会话项目**注册表独立**——code 模式与普通模式的项目级配置
   （AGENTS.md、执行档等）会冲突，必须分开管理；
2. 同一目录常有两类需求（如 code + 数分）：**两册各登记一个项目条目、唯一
   标识符不同**——表面同一路径，实为两个项目实体；不能归了一册另一册就消失；
3. coding 项目与历史对话的**优先级低于普通模式**：不进版块就看不到；进版块后
   普通内容继续可见的同时 coding 内容也可见；coding 内容**不塞进左侧历史栏**
   （臃肿），由版块内容区承载；
4. 存量 coding 项目不做自动迁移，用户在版块内手动打开已有项目即可。

事实约束：会话存储目录是 cwd 的纯函数（`codingAgentSessionShardPath`），与注册表
无关；真正依赖 `config.projects` 的只有两处——runtime 会话目录枚举
（session-catalog-roots.ts）与 fs 信任白名单种子（ipc/fs.ts）；项目生命周期
（校验、ssh:// 登记、ADR-0147 迁移、归档/删除、变更广播）由 ProjectService 单套
承担；会话工作模式创建时固化于会话同目录 `agent-modes.json`（sessionId → mode
索引，每会话恰一个标签），恢复时据此折算 capabilityProfile（ADR-0128）；
`/automation`、`/agents` 等已有"内容区整页 + 全局侧栏保留"的路由先例。

## 决策

1. **版块项目入独立注册表（第二册），条目即实体。** desktop config 新增
   `allstarProjects` 清单；条目含稳定唯一 id、path、name 等。版块的项目空间、
   会话列表只读这一册，普通侧栏只读旧册，不互显对方条目。
2. **路径是条目的引用属性：册内唯一，跨册可重叠。** 同一 cwd 可在两册各有一条
   条目，二者是不同项目实体（id 不同），共享的只是路径与其下的会话池。配置按
   条目归属隔离：root `AGENTS.md` 与既有 `.vetta/policies` 归普通册条目单主；
   开发条目的项目级指令与配置（M1-5：执行档/工具面/围栏 scope）落在 `.vetta`
   内的版块命名空间（如 `.vetta/allstar/`），由版块会话创建链路注入，两类条目
   互不读写对方的配置面。普通册存量条目无 id 时以路径为标识（向后兼容，不回填）。
3. **cwd 级共享设施读两册并集、按 cwd 去重**：会话目录枚举与 fs 信任种子改为
   `projects ∪ allstarProjects`（含各自 archived）去重后的路径集。会话身份、
   存储位置、ADR-0128 的 capabilityProfile 折算全部不变。
4. **生命周期单套服务、按条目操作**：新建/导入/打开/移除/归档共用 ProjectService
   的校验、远程登记与广播路径，仅落点清单不同。移除版块册条目只删该条目，不动
   目录、不动普通册条目；目录级破坏性动作（从磁盘删除）作用于整个目录，执行前
   检查两册无另一条目引用（有则警示/要求先处理）。
5. **可见性：会话按模式标签单一归属，默认互隐，版块内全可见，侧栏永不加载
   coding 内容。**
   - 普通侧栏：普通册条目 + 该路径下 **work** 会话（coding 会话从列表与置顶
     过滤）；
   - 版块面：版块册条目 + 该路径下 **coding** 会话（项目空间 `/allstar/$cwd`
     只列 coding；徽章/归档/删除沿用）；
   - 版块态"普通+开发同屏" = 侧栏（普通，不因进版块变化）与版块页（开发）
     并存；打开 coding 会话仍走现有聊天路由，版块入口保持高亮；
   - 只在版块册登记的目录，其 work 会话不进任何列表（搜索/深链仍可打开）；
     需常态使用则同时登记普通册；
   - 过滤是列表视图规则，不是权限边界（ADR-0128"可见性≠授权"精神）。
6. **列表层补模式字段**：`listSessions` 返回的会话信息增加 `agentMode`（从
   agent-modes.json 批量解析，不逐个读 JSONL）；普通侧栏过滤、版块过滤与徽章
   统一以此为准，不产生第二个模式事实源。无记录的历史会话按 work 计（与
   LEGACY 恢复口径一致）。
7. **存量不迁移，"打开已有项目"= 在版块册新增条目**：用户在版块内打开已有目录
   （无论普通册是否已有条目）即登记一条版块册条目，普通册原样；移除条目即
   "移出版块"。均幂等。版块首页"近期开发会话"聚合**全部** coding 会话（不限册、
   含默认「对话」项目下的），未登记目录的 coding 会话由此可达，并提供一键
   "归入版块"，保底满足"进版块即见 code 历史"。

## 备选方案

- **复用注册表 + meta.json 归属标签**：否决（用户裁定）——同目录双读者下项目级
  配置无法单主。
- **同路径互斥单归属（归版块则退出普通册）**：否决（用户裁定）——双需求目录是
  常态；冲突的正解是条目级配置隔离，不是路径独占。
- **独立注册表 + 全套独立服务**：否决——校验/信任/ssh/迁移复制两套必然漂移；
  共享设施本就是 cwd 级，并集去重即可。
- **进版块后侧栏加"开发"分组**：否决（用户裁定）——往侧栏堆实体列表臃肿，且与
  版块首页职能重复。
- **存量自动迁移**：否决（用户裁定）——手动打开即可，且新增条目不改变普通侧栏
  归置，无自动迁移的收益。

## 后果与边界

- 两处并集点（会话枚举、信任种子）是版块条目的生命线，且必须按 cwd 去重——
  漏读表现为"在册但会话不可见/fs 拒绝访问"，漏去重表现为同路径双册登记时
  会话重复列出。均列为合同测试点。
- 同路径双册登记时，普通侧栏与版块项目空间各取自己模式的会话，无重复展示；
  两册条目对用户呈现为两处入口，删改互不影响。
- 默认「对话」项目永在普通册；其下 coding 会话经版块首页近期会话可达，不进
  版块项目列表。版块无默认虚拟项目，新会话必须落在具体条目上。
- `.vetta/allstar/` 命名空间与版块会话创建链路的注入机制（指令如何生效、是否
  屏蔽 root AGENTS.md 对开发条目的语义）在 M1-5 任务内定；本 ADR 只约束"条目
  隔离、互不读写对方配置面"。
- M1-6 验收口径：版块册登记/移除幂等；同路径双册登记时两册列表各自正确（普通
  侧栏无 coding、版块面无 work）；未登记目录的 coding 会话在版块首页可达；
  普通侧栏 coding 过滤正确（列表+置顶）。无迁移器。
