# ADR-0146：仓库协议与确定性控制器承载自主研发

## 状态

软件合同已实施并在临时 Git/进程环境验证；真实模型、隔离环境、UI 与发布部署尚未验收。完整目标和实际状态见 [PLAN-0019](../../project/plans/PLAN-0019-autonomous-development.md)。

## 背景

Open Forge 已有 Task 台账、Worktree、测试和发布入口。Magpie 的复盘机制和用户提供的 v2 方案需要可靠的调度与取证，不能依赖某厂商提示词记住所有约束，也不能把模型自述当成验证事实。

## 决策

- REQ/PLAN/TASK 继续表达目标与工作合同；控制器状态仅表达租约、进程、尝试与证据，不新增 GOAL 台账。
- `scripts/agents` 是开发工具，依赖现有 worktree 与质量入口，产品 Runtime 不引用它。执行器采用闭合 JSON 合同和固定命令数组，模型不生成 shell 命令模板。
- 首版只支持单机控制器。状态使用排他锁、原子替换和 HMAC，租约以 task/run/holder/generation fencing；未知或仍存活的旧执行不能回收。它不是分布式存储或 OS 沙箱。
- 身份由运行器记录；未知作者不能冒充 human。评审、真实测试结果和人工批准分别绑定最终代码、策略、配置与合同。合并候选重新评审、验证，目标分支前进后拒绝旧候选。
- 人工闸门只接受可信控制面公钥验证的外部签名。签名代码不在 Worker 中，批准不扩大能力；真实 Provider、稳定晋升和发布仍遵循用户授权。
- UI 源审计只报告可检测违规与覆盖空白，运行/视觉缺失时拒绝自动验收。实际环境由操作者提供；当前未配置即保持能力关闭。

## 备选方案

- 各厂商工作流独立存状态：规则、身份和重试语义会分叉，未采用。
- Git 分支/notes 作为租约数据库：不能单独处理本机进程、原子事务和失效 Worker，未采用。
- 新建 GOAL 状态机：与现有 REQ/PLAN/TASK 重复，未采用。
- SQLite/远端队列：具备更强事务与跨机扩展空间；首版无此部署条件，也不新增依赖。出现真实跨机并发需求时重新决策，不把本机文件锁延伸为网络锁。

## 后果与恢复

### 2026-10-20 执行环境取证与 UI 接口收敛

用户选择 WSL2 并延期真实 CI/UI 验收。保持既有控制面/Worker 边界，通过仅控制器可访问的 trusted-execution/execution-proof 文件将资源所有者的部署证明接到模型启动和验证入口；签名绑定 Git common-dir、策略、执行器和最长 15 分钟生命周期。它不是检测/创建 OS 沙箱的实现，也不能由 Worker 自述证明。没有真实签发服务和经过验证的隔离时继续拒绝运行；合成测试签名不能成为部署证据。

未采用“isolation 字符串非 none 就可运行”：配置声明无法证明 WSL 宿主、控制器状态、公共 Git 元数据及凭据保护。未让 doctor 启动任意 adapter.doctorCommand：健康检查应只读，未知配置命令可能产生费用或副作用。分开返回本地软件、真实执行及发布就绪情况，延期 CI/UI 不阻止写代码，但不能使对应验收通过。既有未启用配置保持兼容；启用方现在必须提供真实证明并按有效期更新，签发私钥不在开发仓库托管。

UI 采用控制器闭合清单、Desktop 独立输入校验和固定 Playwright 回调，应用模块不 import 仓库控制器。运行结果与独立视觉评审分两步：六主题断言/截图/清理通过后等待异家族视觉评审；绑定不变时复核并复用实际运行证据，避免重拍后沿用旧视觉判断。未知清理暂停、证据变化失效，未授予真实 UI 运行权限时只验证软件合同。

本地合同测试可独立于具体模型执行。代价是必须维护控制面隔离、可信公钥、模型适配和实际运行证据；软件测试不能证明这些外部事实。损坏状态、中断准备、未确认清理和失败合并保留现场，按状态和 Git 事实恢复，不静默重置。模型用量未知时记录未知，灰度监控缺失时停止推进。真实自主等级按证据升级，当前目标 L4 不表示已达到 L4。
