# ADR-0132：定时任务无人值守授权分档是 executionMode 的附加轴

## 状态

已接受（PLAN-0012 / TASK-0116）

## 背景

定时任务要在用户不在场时跑完，现有 `executionMode`（`inherit` / `sandbox` / `full-access`）只选择沙盒边界与默认能力面，粒度太粗：要么几乎每条副作用都弹审批卡，要么在 `full-access` 下仍按 L3/L4 风险矩阵逐次询问。产品需要「只放行指定低风险能力面、其余仍走人工闸」的中间档。

这与 ADR-0123 的会话权限轴（`permissionMode`: `default` | `plan`）不是同一问题：Plan 模式是「先对齐方案再动手」的硬闸；定时任务分档是「自动化会话里哪些能力可在现有审批管线内静默放行」。二者正交，不可互相替代。

## 决策

1. **在定时任务上新增可选能力分档**（`permissionTiers`），字段独立于 `executionMode`，不改变三态语义与解析规则。
2. **分档是授权范围的细化，不是旁路**：工具仍进入 `CodingAgentModelCallFrameComposer` 与审批拦截器；分档只影响 Desktop 审批 broker 在自动化会话上是否可对「已授权档 + 非 L4」做静默 `approve`。L4 永远弹窗（与既有 broker 规则一致）。
3. **默认值与现状逐比特一致**：缺省或全关时，自动化会话的审批路径与改前相同（Trust 命中仍可静默、其余弹窗）。
4. **「全部开启」是显式批量操作**，必须经带风险文案的 i18n 确认，不得默认勾选。
5. **计费 / 配额语境一票否决**：无论分档如何配置，涉及配额消耗、付费、积分、订阅权益的审批请求一律保留人工确认。
6. **不做全局免打扰开关**；不做 Plan 模式契约变更；不复制第三方宿主的按钮文案白名单实现。

## 与 ADR-0123 的关系

| 轴 | 所有者 | 作用 |
| --- | --- | --- |
| `permissionMode`（ADR-0123） | 会话 Runtime | 工具面可见性 + 执行闸（Plan 硬闸） |
| `executionMode` | 会话 / 任务 | 沙盒与默认执行边界 |
| `permissionTiers`（本 ADR） | 定时任务 → 自动化会话 | 在既有 L0–L4 审批管线上，细化「哪些已授权能力可无人值守放行」 |

自动化场景拒绝进入 Plan 模式（ADR-0123 §7）仍然成立；分档不能用来绕过 Plan 闸门，因为自动化会话根本不进入 Plan。

## 备选方案

| 方案 | 未采纳原因 |
| --- | --- |
| 扩展 `executionMode` 为更多枚举 | 破坏既有三态合同与持久化；沙盒边界与能力授权被绑死 |
| 全局免打扰开关 | 与 ADR-0123 双闸门冲突，影响面大于定时任务 |
| 在审批拦截器内按分档直接 `block` 未授权能力 | 任务要求未授权仍走正常审批，而非静默拒绝 |
| 复制第三方 CDP 按钮文案白名单 | AGPL 净室约束；本仓已有权限卡与风险矩阵 |

## 后果

- 任务 JSON（`scheduled-tasks.json`）可多一个可选 `permissionTiers` 对象；旧任务无此字段时行为不变。
- Desktop 在创建自动化会话时绑定分档到 sessionId，审批 broker 查询后决定静默或弹窗；会话结束解绑。
- 用户误开「系统级工具」等档位会扩大无人值守放行面——靠「全部开启」确认文案与按档独立开关降低误触；计费语境仍强制人工闸。
