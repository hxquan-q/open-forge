# 规则分级与维护

本文是[根规则](../../../AGENTS.md)按任务触发加载的全仓规则扩展，约束级别不因拆分而改变；更近一级 AGENTS 可收紧。代码路径、命令与原文中的“根文件”均相对仓库根，不相对本文目录。

## 规则分级与豁免

本文件与各级 `AGENTS.md` 的规则分三级（TASK-0111）：**Invariant**（不可破，不接受 waiver）、**Policy**（可登记豁免）、**Guideline**（建议）。各包/目录 `AGENTS.md` 末尾的「规则分级」段给出该文件的组级分类；未列出的要求按 Policy 处理。

本文件的组级分类：

- **Invariant**：`项目概览`/`架构与 ADR` 中的依赖方向与包边界、`AI 与安全边界` 全节、`Git 与并行工作区` 中的破坏性操作与授权边界、`上游同步与改动归属` 的 fetch-only 约束、`TypeScript 与 UI` 中的硬条款（不新增 `any`、不深链、快捷键可配置、面向用户文案 i18n）、生成文件禁手改。
- **Policy**：`开始任务` 的流程要求、`常见任务入口` 指引、`测试与验证` 的覆盖要求、`发布说明与新增包` 的写入要求、`交付要求` 与 `project/` 台账规范。
- **Guideline**：`实施原则` 与 `重构决策` 的取向、代码与注释风格建议。

**豁免**：Policy 级例外必须在 `project/decisions/waivers/` 登记（规则、理由、风险、补偿、owner、到期日）；`bun run check` 中的 `check-waivers` 对到期 waiver 报红。到期不自动撤销也不自动续期，处置由人决定。评审与 Agent 自检清单见 `docs/dev/review-red-flags.md`。
## 维护本文件

- 只加入全仓、长期、无法从代码轻易推断且能防止真实错误的规则。
- 模块规则放到最近的 `AGENTS.md`；低频多步骤流程放到独立文档或 Skill；工具专属能力放到对应工具配置。
- 能由 lint、类型、测试或架构守卫可靠验证的硬规则，应优先实现机械检查；本文件说明意图和正确入口，不替代自动化门禁。
- 新增路径和命令前确认其真实存在。架构、脚本或目录变更使本文件过时时，应在同一变更中同步更新。
- 定期删除模型已能从代码推断、从未影响决策或已经失效的说明，避免关键约束被长文本稀释。
