# 自主研发协议

本扩展在调度 Task、运行外部开发 Agent、导入评审/批准、集成或控制发布时必读。它服务开发协作；产品 Runtime 仍遵循原有合同。

## 执行顺序

1. 读当前 Task、既有任务入口和 [LESSONS](../../../LESSONS.md) 中相关候选；候选供规避已知错误，强制规则仍以权威正文为准。运行策略以 `project/autonomy-policy.json` 为准；有效配置不等于已授权调用模型或发布。
2. 用 `agent:queue` 查看已有 ready Task；依赖须完成且已集成。`agent:claim` 领取同一租约，`agent:prepare` 通过标准 Worktree 入口建立并提交 in_progress 基线。
3. `agent:cycle` 对一个明确 Task 执行有界的实现→独立评审→验证；`--through integrate` 另要求 integrate-dev 能力。代码、策略、执行器或合同变化会使证据失效。运行失败保留源代码和状态，先诊断再恢复。
4. 合并候选在已租用 Worktree 中生成；其评审和检查全部重做。只有最终提交和目标基线仍匹配才前进本地 main；用户接受与发布保持既有独立状态。所有外部推送继续受协作与交付规则约束。

## 闸门与信任

七类人工闸门和未知分类均需批准具体候选。控制器从独立状态目录的 `trusted-humans.json` 读取操作者提供的 Ed25519 公钥；`agent:approval` 只导入外部签名，不提供签名或自称 human 的接口。批准包含代码/策略/合同、覆盖闸门、原因和有效期；它不扩大运行能力或发布权限。私钥、控制器状态与发布凭据只在可信控制面，不挂载给 Worker。

运行目录、环境变量隔离和 `isolation` 配置都不是 OS 沙箱证明。实际 Worker、测试代码和候选构建需在经过验证的 VM/OS 边界内执行，且不能写控制器或读取真实账号。边界未具备时保持模型和发布能力关闭。未知身份、失联进程、损坏状态、过期租约或未运行检查均拒绝自动放行。

## UI 与证据

DESIGN.md 的 D01–D11 是规则编号。源检查只覆盖可解析的新样式/标签；动态样式、交互、布局、i18n 和三主题×明暗仍需实际运行与独立视觉证据。缺少覆盖不能写为自动验收通过。当前尚未提供真实 UI 运行适配器时，运行器必须拒绝 UI 自动验收。

命令、恢复条件和软件证明边界见 [运行工具](../../../scripts/agents/README.md)；整体进度和未完成项见 [PLAN-0019](../../../project/plans/PLAN-0019-autonomous-development.md)。经验晋升只形成规则修改候选，仍走规则治理与人工闸门。

## 反馈与复盘

外部信号按来源事件去重，形成 `needs-investigation` 建议；完成调查后复用已有 REQ/Task 建立工作合同。采集与建议不授予对外回复或自动实施权限。每日复盘使用 Asia/Taipei 的明确日期，读取实际 commit 和失败运行，围绕返工、不该合并、验证不足产出规则、原因和证据。证据时间决定 Seen 日期，同一证据重放不增加计数；三日期只生成候选，权威规则按治理入口修改。候选存放与导出见 [LESSONS](../../../LESSONS.md)。

## 发布与中断恢复

`agent:publish` 只接收已集成、重新评审及验证的最终提交。另需绑定同一候选和制品的可信 CI（三平台单测与 packaged）、三平台签名验证回执，控制器核对实际文件 SHA-256 与大小。受信发布器在独立控制面实现固定命令、幂等查询及现有发布流程；配置与签名回执协议不能代替该服务的部署验收。默认发布器关闭。

服务回执由操作者配置的独立公钥验签；CI、制品、发布、遥测和资源清理分别声明角色。发布意图先落盘，只有实际回执才记录 published/paused；响应丢失必须先 reconcile。灰度每阶段需要完整观察窗口、三平台新鲜遥测及足够样本；超阈值或失去监控要求暂停，暂停失败保留未知状态。已安装版本的回退继续遵循现有产品更新合同。

控制器中断及未确认进程清理保留现场。资源所有者确认进程树、挂载与凭据均已撤销后，导入绑定资源和 generation 的 cleanup-proof；不根据父 PID 不存在就放行。该操作保留全局暂停，操作者核查现场后再 resume。未知发布仍须对账，失败准备和合并仍须检查实际 Git 状态。
