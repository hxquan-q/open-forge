In the tables below, `~` means the current system user's home directory. The desktop UI is the preferred configuration entry point; direct file edits are for development, diagnosis, and controlled migration.

## Data roots and compatibility migration

- Installed builds and the CLI default to `~/.openforge`; the normal Desktop `bun run dev` command defaults to `~/.openforge-dev`.
- `VETTA_HOME` overrides the complete data-root path (with `~` expansion) and takes precedence over the directory-name setting. `VETTA_CONFIG_DIR` selects the data-root directory name under your home directory. Keep host and sidecar settings consistent.
- When the default new root is absent, the old `~/.vetta` exists, and no different root is selected, the app attempts to rename the old root to `~/.openforge`. If renaming fails, it continues using the old root. If both exist, it uses the new root without merging them.
- The `distribution` (Allstr ai) and `self` (Open Forge) profiles share these paths. Switching brands does not isolate data.
- Project-local `<cwd>/.vetta/` remains a compatibility contract distinct from the global root. Do not rename it in bulk.

The table below uses the installed-build default; substitute the appropriate prefix for development or a custom root.

## Global paths

| Path | Contents |
| --- | --- |
| `~/.openforge/agent/settings.json` | Global Coding Agent settings |
| `~/.openforge/agent/models.json` | Custom providers and model overrides |
| `~/.openforge/agent/auth.json` | Login, OAuth, or manually configured credentials |
| `~/.openforge/agent/mcp.json` | MCP server configuration |
| `~/.openforge/agent/sessions/` | Session files organized by safe cwd |
| `~/.openforge/abilities.json` | Installed capability index |
| `~/.openforge/skills/` | User-level skills |
| `~/.openforge/scene/` | User-level scenes |
| `~/.openforge/plugins/` | User-level plugins |

Set `VETTA_CODING_AGENT_DIR` to override the Agent directory. The host, sidecar, and migration tools must use the same value or sessions and configuration will split across directories.

## Project paths

| Path | Contents |
| --- | --- |
| `<cwd>/AGENTS.md` | Long-lived project instructions automatically loaded by project sessions |
| `<cwd>/.vetta/settings.json` | Project overrides for global Agent settings |
| `<cwd>/.vetta/skills/` | Project-level skills |
| `<cwd>/.vetta/extensions/` | Project-level Coding Agent extensions |

Relative paths in project settings resolve from the directory containing `.vetta/settings.json`. Project configuration takes precedence over global configuration.

## Editing and migration rules

1. Prefer the Open Forge settings page so runtime validation and related state stay synchronized.
2. Close active sessions before manual edits to avoid racing with a writer.
3. Never let two processes write the same session file.
4. Preserve directory structure and file names during migration; do not copy only one session body.
5. Before deleting anything, distinguish original sources, processed results, session history, and artifacts because their retention semantics differ.

<Callout type="info" title="Paths are implementation facts, not cross-version contracts">
  Automation should prefer the public SDK, RPC, or exported capability. Do not depend on an internal directory unless this documentation explicitly promises it.
</Callout>
