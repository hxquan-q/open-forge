<Takeaways>
  <li>No account or subscription for the default lite build</li>
  <li>At least one working default model</li>
  <li>A local project that can be opened and used for a session</li>
</Takeaways>

Start with this repository's default lite build: configure your own model, open a local project, and create a session. A full distribution only uses cloud authorization when its distributor provides a compatible backend and setup instructions.

## Before you start

| Requirement | What to prepare |
| --- | --- |
| Computer | Windows, macOS, or Linux; use [GitHub Releases](https://github.com/hxquan-q/open-forge/releases) as the source of truth for available builds |
| Build mode | Lite needs no account; full login depends on the distributor's configured service |
| Model service | Your endpoint and key under **Settings → Model configuration**; organization models require a build and service that actually provide them |

## Install and launch

1. Download the installer for the current operating system and CPU architecture from [GitHub Releases](https://github.com/hxquan-q/open-forge/releases).
2. Launch Open Forge and complete the first-run guide. Choose the UI language and appearance, grant macOS permissions when requested, and finish browser authorization if needed.
3. Enter the workspace directly in lite. For a full build that requires an account, follow its distributor's authorization flow; use **Re-authorize** if its login link expires.

## Configure a model

Open **Settings → Model configuration**. Choose a preset provider, enter its API key, pull the model list, and set one model as the default. For a custom provider, configure its API type, Base URL, model ID, and key explicitly.

<Callout title="Keep keys private" type="warn">
  Enter API keys only in the credential configuration UI. Do not put keys in prompts, project files, logs, or issue reports. Local model configuration is stored under `~/.openforge/agent/models.json`.
</Callout>

## Ready-to-use checklist

<Checklist title="Before the first task">
  <li>Lite has opened the workspace; a full build requiring an account has completed its authorization.</li>
  <li>At least one model is configured and selected as the default.</li>
  <li>A new session can select the model without a credential or connection error.</li>
  <li>The correct project directory is open.</li>
  <li>You understand whether the session uses restricted sandbox or full access.</li>
</Checklist>

If a model test fails, fix the provider configuration before retrying a task. Continue with [your first task](/getting-started/first-task/) or [model configuration](/product/models/).
