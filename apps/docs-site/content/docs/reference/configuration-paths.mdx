下表中的 `~` 表示当前系统用户目录。桌面界面是首选配置入口；直接编辑文件适合开发、诊断和受控迁移。

## 数据根与兼容迁移

- 正式安装和 CLI 默认使用 `~/.openforge`；Desktop 的普通 `bun run dev` 默认使用 `~/.openforge-dev`。
- `VETTA_HOME` 可覆盖完整数据根路径（支持 `~` 展开），优先于目录名设置；`VETTA_CONFIG_DIR` 用于选择用户目录下的数据根名称。宿主与 sidecar 应使用一致的配置。
- 默认根尚不存在、旧 `~/.vetta` 存在且未选择其他根时，会尝试将旧根改名为 `~/.openforge`；改名失败则继续使用旧根。新旧根同时存在时优先使用新根，不会合并二者。
- `distribution`（小爱ai / Allstr ai）与 `self`（Open Forge）共用这些路径，切换品牌不会隔离数据。
- 项目内的 `<cwd>/.vetta/` 仍是兼容合同，与用户全局根不同；不要将它批量改名。

下表按正式安装的默认根列出；开发或自定义根请替换相应前缀。

## 全局路径

| 路径 | 内容 |
| --- | --- |
| `~/.openforge/agent/settings.json` | Coding Agent 全局设置 |
| `~/.openforge/agent/models.json` | 自定义 Provider 和模型覆盖 |
| `~/.openforge/agent/auth.json` | 登录、OAuth 或手动凭证记录 |
| `~/.openforge/agent/mcp.json` | MCP 服务配置 |
| `~/.openforge/agent/sessions/` | 按安全 cwd 组织的会话文件 |
| `~/.openforge/abilities.json` | 已安装能力索引 |
| `~/.openforge/skills/` | 用户级技能 |
| `~/.openforge/scene/` | 用户级场景 |
| `~/.openforge/plugins/` | 用户级插件 |

可以使用 `VETTA_CODING_AGENT_DIR` 覆盖 Agent 目录，但宿主、sidecar 和迁移工具必须使用同一值，避免会话和配置分裂。

## 项目路径

| 路径 | 内容 |
| --- | --- |
| `<cwd>/AGENTS.md` | 项目长期指令，供项目会话自动加载 |
| `<cwd>/.vetta/settings.json` | 覆盖全局 Agent 设置 |
| `<cwd>/.vetta/skills/` | 项目级技能 |
| `<cwd>/.vetta/extensions/` | 项目级 Coding Agent Extension |

项目设置中的相对路径相对于 `.vetta/settings.json` 所在目录解析。项目级配置优先于全局配置。

## 修改和迁移原则

1. 优先通过 Open Forge 设置页修改，确保运行时校验和关联状态同步。
2. 手工编辑前退出相关活动会话，避免与正在写入的进程冲突。
3. 不让两个进程同时写同一个会话文件。
4. 迁移时保留目录结构和文件名，不只复制单个会话正文。
5. 删除前分清原始资料、整理结果、会话历史和产物，它们的保留语义不同。

<Callout type="info" title="路径是实现事实，不是跨版本协议">
  自动化工具应优先使用公开 SDK、RPC 或导出能力。除文档明确承诺的配置文件外，不要依赖未公开的内部目录结构。
</Callout>
