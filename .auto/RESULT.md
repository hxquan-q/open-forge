# 流式 Markdown 渲染性能优化 — 成功记录

> 会话：autoresearch/60 轮自主实验 · 分支 `autoresearch/markdown-stream-perf-20261022`
> 基线：`main@537af26` · 工作区：`open-forge-wt/autoresearch-md-stream`（主检出未受影响）

## 一句话结论

Agent Desktop 聊天中逐字输出的 AI 回复，**最差单帧渲染耗时从 50.6ms 降到 0.9–4.1ms（-92%~98%）**，三夹具总渲染耗时从 **1252ms 降到 142–169ms（-88%）**，渲染结果与优化前**逐元素一致**。

## 一、数据对比

### 主基准（仓库既有 `apps/desktop/scripts/markdown-render.bench.mjs`）

真实 Chromium + React production profiling 构建，三个夹具（长正文 32.9k 字符 / 大表格 21.9k / 长代码 60.9k），每次 50ms 追加、共 40 次流式更新。

| 指标 | 基线 | 优化后 | 变化 |
|---|---:|---:|---:|
| 三夹具总渲染耗时（干净负载带） | 1252.0 ms | **142.5 ms** | **-88.6%** |
| 最差单帧 commit（p95，干净带） | 50.6 ms | **1.6 ms** | **-96.8%** |
| prose / table / code（干净带） | 625.8 / 544.9 / 81.3 | 38–44 / 76–94 / 26–36 | -93% / -85% / -62% |

### 负载带口径（重要）

优化机是开发机，负载抖动大（同一份代码总量可差 60%）。**总量必须按负载带表述，p95 才是稳定信号**：

| 负载带 | 总量 | p95 最差 commit |
|---|---:|---:|
| 干净 | 142–169 ms | 1.3–1.6 ms |
| 中等 | 190–215 ms | 1.8–2.2 ms |
| 恶劣 | 229–286 ms | 2.1–4.1 ms |

**20 次跨带采样中 p95 始终在 0.9–4.1ms**——优化作用于「每一帧要解析/渲染多少工作」，与机器快慢无关。这是最可靠的结论。

> 基准使用 `react-dom/profiling` 构建（含 Profiler 开销），生产构建实际更优。数字只用于同机对比，不作为跨机器门槛。

### 单形态专项（独立诊断脚本，夹具更极端）

| 内容形态 | 夹具 | 优化前 p95 | 优化后 p95 |
|---|---|---:|---:|

## 二、优化了什么

### 核心诊断（先测后改）

相位剖析定位到真正的瓶颈**不是 React reconcile（全程仅约 38ms），而是 micromark 重复解析**：长回复若没有代码围栏就永不冻结，每个快照都要把 30k+ 字符整篇重新 tokenize。插件集隔离进一步确认：表格解析 85% 成本在 `remark-gfm` 的表格扩展内部（上游），无可本地优化空间。

### 七项结构优化

| # | 手段 | 作用 |
|---|---|---|
| 1 | **稳定块冻结扩展** | 已完成段落/列表/引用/表格在结构完成时冻结复用；严格守卫防住 link-ref/footnote 追溯、列表/引用/表格续行、rich HTML 上下文与前缀性 |
| 2 | **快照节奏自适应** | 按实测解析成本按占空比（×10）调节快照间隔，快升慢降，上限 800ms |
| 3 | **已提交子树整体 bail** | append-only 下 O(1) 复用块数组引用，reveal tick 间已冻结子树完全跳过 |
| 4 | **增量稳定块扫描器** | 流式期间只扫新增行（原为每 tick 全文 O(N) 扫描），带边界恢复态与 COW |
| 5 | **表格快路径** | 稳定行元素缓存 + 变化后缀迷你解析（每次快照只解析表头+新增行）；回放克隆也缓存，React 整行子树跳过 |
| 6 | **未闭合围栏直渲染** | 尾块是单一未闭合围栏时解析结果确定，零 markdown 解析直接交给代码块组件 |
| 7 | **列表快路径** | 首项定类型/起始号、稳定项元素缓存、`ul`/`ol` 注入器；`<ol>` 编号按 DOM 位置与缓存项保位 |

### 内容形态补齐（每种都先量化再决定）

括号块乐观冻结（定义行到达时同帧重置）、`$$`/HTML 字面量区闭合提交（含嵌套深度感知闭合）、`details` 折叠块、中等构造阈值下调（12k→2.5k）、含链接表格、CRLF、CJK/数学/转义管道、任务列表。

### 代码量

16 文件，**+2693 / −92 行**（含测试）。核心：
`stable-blocks.ts`（冻结+扫描器 +490）、`MarkdownContent.tsx`（快路径选择与接线 +241）、新增 `tail-table.tsx` 247 / `tail-list.tsx` 211 / `tail-fence.tsx` 97；新增测试 `streaming-mixed.test.tsx` 818 行。

## 三、正确性保证

**每一个改动都配了「渲染结果不变」的验证**，不是只看性能数字：

- **守卫矩阵 + property test**：字符级逐字追加下，已提交块恒为严格前缀、拼接恒等于原文（唯一例外：定义行到达时的单次收缩）
- **DOM 等价性模糊测试**：流式渲染 vs 整篇渲染，逐根元素比对（10 份棘手文档 + 含链接大表 + 混合链路 + 八形态全组合）
- **快照新鲜度回归**：防「节流期间内容停更」
- **过渡矩阵**：表格/围栏/数学/括号/定义/CRLF/CJK 全组合的流式链路等价
- **连续同类构造压力变体**：双表/三列表类型/双围栏类型/连续数学组/连续 details

### 测试体系自己抓出并修复了 7 个真 bug

| bug | 性质 |
|---|---|
| 部分行冻结的前缀性漏洞 | `- a\n\n1` 冻结后，`1.` 到达会翻转守卫 → 罕见 un-freeze 重挂 |
| 围栏闭合行 `text.length` 依赖 | 增量扫描器恢复态错误（幽灵提交） |
| 边界快照 index 偏移 | 快照在 `index = lineEnd` 前拷贝 → 恢复时重复处理 |
| 嵌套 HTML 提前截断 | 内层 `</div>` 截断区域 → 提交块含未闭合外层（**渲染分歧**） |
| **僵尸闭合正则** | 提交分支未清 `literalEnd`，连续 `$$` 区持续误闭合（**潜伏 12 轮**，被八形态混合测试首执行即抓到，一行修复） |
| 迷你前缀多出空行 | 使 `li` 行号整体偏移一格 → 缓存键错位（列表快路径首版失效根因） |
| 检测状态短路 | `separatorPending = pending && isBare` 恒假 |

## 五、局限与未做

| 项 | 状态 |
|---|---|
| **纯长引用流**（p95 18–39ms） | 模块实现完整、jsdom 缓存验证通过，但浏览器中快路径参与度逐轮漂移（时序脆弱）；**已备档**，重启条件：先稳定复现漂移 |
| **Worker 异步解析** | 唯一能进一步压低单帧的路径；**被依赖政策封锁**——主线程需要 `hast-util-to-jsx-runtime`（非 theme-ui 直接依赖，新增需授权） |
| 流结束转换 | 单次 28.3ms（表格冻结为提交块时全量重挂）；已量化，判定不值得架构手术 |
| 段落分组挂载 | 净收益约 3ms 且引入重解析，弃 |
| 括号块后接引用定义 | 定义行到达时整条流剩余部分回退常规解析（保守等价，正确性优先） |

## 六、方法论沉淀

1. **交错 A/B 是时变负载下唯一可信对照**（本会话两次结论因此翻转）
2. 隔离环境 + 键位插桩定位缓存类缺陷，比集成环境试错快一个量级
3. 单一构造测试对「连续同类构造」类缺陷盲——混合压力测试是必要层
4. 诊断夹具的追加内容必须与夹具同形（否则检测必然失败，误判为产品问题）
5. 硬断言不可降级为日志（会掩盖真实失败）
6. 插桩读值须在 reset 前读；`memo` bail 不执行函数体（计数要放函数体内）；`HTMLCollection` 是活集合
