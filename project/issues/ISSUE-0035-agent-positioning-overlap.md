# Agent 定位重合的处置

## 背景与已知事实

- 2026-10-26 用户在 TASK-0406（档位归属）走查时提出：现存智能体中**存在定位重合**的条目，
  后续需要讨论如何处理；未点名具体条目。
- 候选重合面（待与用户逐个核对）：宿主预置 `preset-agent` 提供的装机人设、各插件贡献的
  专属智能体（如各流水线角色）、用户自建档案——三者可能覆盖同一类工作（如「写代码的」
  或「做设计的」同时存在内置人设与插件版本）。
- TASK-0406 落地后，档位归属已把「开发向」与「普通向」分到两个视图，重合问题被收窄到
  **同档内部**。

## 未决问题

1. 重合条目的判据是什么：名字相似？职责相似？用户实际选择率？
2. 处置方向：合并/下架内置人设、按档位隔离、给用户显式的「隐藏/收藏」、还是接受重合并只做
   分组排序？
3. 宿主预置人设（preset-agent）在 M2 流水线并入宿主后的去留（与 allstar 角色可能重合）。

## 候选方案与取舍

- A. 按档位 + 分组排序先缓解，不动档案本身——成本低，但重合仍在。
- B. 下架被插件取代的内置人设（沿用 `legacyIds` 接管机制）——干净，但需要逐个判定归属。
- C. 选择器给用户隐藏/置顶能力（个性化）——灵活，但把整理成本转嫁给用户。

## 推荐方案

先 A 后 B：M1 版块壳的选择器分组落地时顺带按档位收窄展示面；M2 流水线并入后集中做一次
人设盘点（preset-agent vs allstar 角色）再决定下架清单。

## 决策触发条件

- M2（流水线并入宿主）启动时的人设盘点；
- 或用户点名具体重合条目时随时讨论。

## 后续可能拆出的 Requirement/Task

- 人设盘点与下架清单（挂 M2）；
- 选择器分组/排序（可并入 TASK-0405 版块壳范围）。
