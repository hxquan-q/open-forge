# 会话归档跨设备迁移的两个产品缺口：导入位置自选与产物打包

## 背景

TASK-0349 交付后用户追问跨设备场景：① 导入到另一台设备/不同位置时能否**自主选定导入位置**；② 导出能否**把产物（项目目录内容）一起打包**。两者目前均不支持，属现行设计的真实边界，不是缺陷。

## 已确认事实（TASK-0349 调查与跨实例回归）

- 导入落点完全由归档内记录推导：记录有项目 cwd → 本机 `<agentDir>/sessions/--编码路径--` 分片；默认对话/IM/KB cwd → 各自专用目录；无 cwd → 默认对话目录。无目标选择步骤。
- 会话列表、打开与续跑绑定记录内 cwd；指纹幂等依赖记录**原样**写入（身份键别名化，cwd 参与指纹源）。
- OFAR 只含会话记录；格式有 `attachments` 字段但定位是会话附件字节，桌面导出未采集；产物是项目 cwd 下的真实文件，不在包内。
- 并列识别 `<项目>/.vetta/sessions`（存量兼容，仅本地项目）：整目录 zip 搬运 + 同路径登记可让旧布局会话可见，但新会话均落全局分片，一般不适用。

## 未决决策

### ① 导入目标位置选择

- 方案 A（仅改落点）：导入对话框加「目标项目」选择，副本落所选项目分片、记录原样。**风险**：会话出现在项目 X 而记录 cwd 指向旧路径，续跑工作目录错位（另一设备上不存在）→ 不建议单独做。
- 方案 B（项目迁移向导，推荐）：选归档 → 选/新建目标项目路径 → **重写记录 cwd 至目标路径** + 恢复会话（可选产物）。需先定义「重写后指纹仍按原始记录计算」的规范，否则重复导入幂等失效。
- 不做：维持现状，文档说明「两台设备用相同检出路径即可」。

### ② 产物/整目录打包

- 方案 C（完整项目备份）：项目级「会话 + 工作区」迁移包。载体二选一：扩展 OFAR 增加 project payload（沿用加密与流式帧）或独立 zip（可选口令）。需定排除规则（node_modules/.git 可选排除）、导入冲突策略（跳过/覆盖/合并）、体积边界，远程项目需走 SSH 传输（复用 REQ-0012 基建）。
- 方案 D（仅产物引用清单）：包内记录产物文件清单与 hash，不打包字节；导入时提示缺失。轻量但恢复体验差。
- 建议与 ① 的方案 B 合并为「项目迁移」一个特性立项，避免两个半成品入口。

## 决策触发条件

用户裁定范围（做 B+C / 仅 B / 仅 C / 维持现状）后转 REQ + 实施 Task；实施前需 ADR 记录 cwd 重写与指纹规范（若选 B）。
