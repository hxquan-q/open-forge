## 2026-10-20 最新决策与执行边界

用户决定只使用现有 WSL2，当前不准备其他机器或 Windows VM；真实 CI 待账号额度恢复后运行，真实 UI 验收也延后。这改变实施次序，不改变 REQ-0019 的完整 L4 目标，也不把未运行的检查改成通过。

当前先交付仓库软件与本地验证能力；完整 L4 继续表示真实模型能够在已验证边界内，完成目标内普通任务的实现、独立评审、验证、授权集成与发布，并能处理故障、监控和经验回流。没有独立评审、有效执行边界、三平台/UI 证据或发布遥测时，不宣称完整 L4。

| 已确定事项 | 当前安排 | 不得推导为 |
|---|---|---|
| 只有 WSL2 | 将其作为 Linux 开发执行环境；仓库副本和 Bun/Node/Git 依赖在 Linux 内单独安装，受控验证后再接自动流程 | Windows Worker、Windows/macOS 实机验收或天然安全沙箱 |
| CI 额度暂不可用 | 先做本地定向、impact 和完整 check；保留待执行提交及命令，额度恢复后验证最终候选 | 绕过远端检查、修改 CI 预算或已有发布条件 |
| 真实 UI 验收延期 | 先完成适配器、报告校验与失败/清理测试；命中 UI 的运行停在待验收阶段 | 仅凭源码审计、普通单测或截图放行 UI Task |
| 模型和发布环境尚未提供 | 软件合同用受控替身测试；真实调用、身份、usage、签名与遥测另取证 | 模拟替身等于真实模型质量或可发布状态 |

本机只读预检 `wsl.exe --list --verbose` / `--status` 均 exit 1，返回未安装 WSL；尚不能记录当前会话的 WSL2 已就绪。若用户所指为其他环境，部署时从该环境核验，不自动安装、不更改宿主设置。

微软的 [WSL 安全模型](https://github.com/microsoft/WSL/blob/master/doc/docs/technical-documentation/security.md) 说明发行版不是与宿主之间的安全边界。保留 WSL2 方案，但必须单独证明 Worker 无法访问控制器、真实账号和发布密钥；可调查宿主不同 OS 身份及访问控制等方案，不预先宣称其满足合同。当前不要求购买新机器，隔离未证明时也不启用自动模型执行。

## 候选方案与取舍

采用仓库协议、确定性执行与可替换模型进程；不把多厂商 CLI、Git notes 或提示词当作安全边界。运行记录采用单写者、原子持久化和租约 fencing，Task 继续是语义合同。跨机器共享存储以后只能在明确的存储合同上扩展，不能把普通本地锁称为分布式锁。

## 按最新决策实施

本次用户已明确要求实施；当前范围收敛为 TASK-0328 UI 接口、TASK-0330 环境检查和 TASK-0331 明确任务的本地闭环。暂无问题来源，TASK-0329 先搁置，不再阻塞 readiness；planner/triage/lessons 自动建任务不属于本次闭环。后续 WSL2 预检已确认 Ubuntu-26.04 Running / Version 2，下面历史“未安装”结果不再代表当前状态。实际 Linux 验证使用专用临时副本，Bun 1.4.2 / Node 22.14.0，不复用 Windows node_modules，也不代表产品全仓 Linux 构建或真实模型运行已验收。

### A. 立即完成仓库软件，不等待远端额度

1. TASK-0328：完成现有 UI 草稿，修正语法/缺模块，接通显式授权、fresh Profile、真实断言报告、候选绑定和超时清理；只运行适配器合同与故障测试，真实 UI 运行延期。
2. TASK-0329：完成有上限的 GitHub/CI 只读采集与信号去重；用受控进程验证正常、限流、断网、解析失败和恶意正文。没有 CI 新运行不能报采集到新的成功；不创建定时任务或对外回复。
3. TASK-0330：完成分项 readiness；区分本地软件、模型执行与完整发布条件，每项保留证据、原因和未执行项。延期项目不能被标为通过，也不能妨碍无关的本地代码测试。
4. 补齐角色到工作流的消费路径：planner 建议经合同校验形成 Task 草稿，triage 进入可复现调查，lessons 消费真实复盘材料形成候选；外部内容和模型输出不能直接生成已授权的 ready Task 或强制规则。TASK-0326 的角色入口不等于这些路径已实现。
5. 核对调度依赖：`queue.mjs` 当前只把 `done + integrated` 算完成。内部工程任务按现有交付合同验收；需要人工接受的功能保持 verifying。若要引入“工程已完成即可供后续任务依赖”的区别，先另建治理 Task、合同测试与迁移说明，不把 verifying 全部改成 done。
6. 完成文档与本地验证后按 concern 原子提交；不能为了收尾夹带现有 UI 草稿或他人 temp 文件。代码阶段跑最低充分行为测试、impact 和完整 check；本轮计划更新本身不表示这些代码已完成。

第 4、5 项是从实际源码发现的接线工作，不能假定已有命令会自动完成；实施前按现有 Project 路由补相应 Task，避免扩大 TASK-0328–0330 的责任边界。

### B. 在 WSL2 验证真实开发闭环

先核实实际 WSL2 发行版、资源、Linux 文件系统仓库副本及 Bun/Node/Git 兼容性；不复用 Windows 的 node_modules，不直接把当前带未提交改动的工作区当作已提交基线。控制器状态、日志和工作副本都用专用目录，不读取真实 Desktop 状态。

真实模型启动前，固定可调用的实现者和异家族评审者、实际模型身份及必要授权；验证 Worker 的 OS 权限/凭据隔离和整个进程树回收。模型可执行文件存在或 CLI 已登录不能替代以上条件。当前这些条件未满足，level=0 和 disabled 保持。

满足后先单任务、单实现者运行，沿公开入口完成领取→实现→异家族评审→本地验证→合并候选重新评审和验证→按现行权限集成。测试/UI/远端检查缺失时停在对应待验收点，普通代码任务不得借延期越过必要检查。以后才增加连续多 Task 和定时调度。

故障验收必须包含：评审拒绝、候选改变、目标分支前进、执行超时、控制器重启、租约过期/旧 Worker 回包、资源清理不确定。预期是留下可诊断证据、拒绝重复集成、未知清理暂停；恢复不能清空状态或伪造成功。

### C. 用户指定的延期验收

账号额度恢复后，由当前最终候选重新取得三平台 CI 与 packaged 检查，不能复用旧提交的绿色结果。真实 UI 验收在明确授权后运行受影响用户流程、交互/布局断言、三主题×明暗和独立视觉检查；失败进入修复与相应回归。UI 可用性不是 CI 额度的同一事实，本次二者均依用户决定延期。

这段延期阻止完整跨平台/UI 验收和依赖这些证据的发布，不阻止 A 段的软件编写。额度恢复前不循环触发失败 CI，不修改预算，也不安排未经请求的定时提醒。

### D. 完整 L4 的最后验收

部署并验证独立控制面的签名/制品/发布/清理服务与真实遥测；同一最终提交的检查、独立评审、制品摘要及可信回执必须一致。发布响应丢失先对账、不能盲重试；崩溃超过阈值或遥测缺失时确实暂停，恢复需要健康观察与显式恢复动作。

现行策略灰度为 1%→10%→50%→100%，每阶段 48 小时，最低样本 500，遥测新鲜度 15 分钟。样本不足继续等待，不造流量或静默降低门槛；如需调整，另走策略治理。

稳定分支、tag、Release、上传和部署继续按仓库既有明确授权执行。若未来希望普通 patch/minor 发布在限定范围内自动进行，须先明确范围并更新权限合同，不能把本次“看看怎么实现 L4”解释为已授权。七类人工闸门、未知分类与目标冲突仍保留。

完整 L4 的验收包必须同时含 A 的实现与软件测试、B 的真实模型/隔离/故障证据、C 的最终候选跨平台/UI 结果，以及 D 的真实发布/监控结果。没有固定“一个月自动达标”的时间承诺。

## 不做什么

不把内部试点当最终完成，不修改真实用户配置，不绕过七类闸门，不调高检查基线或 CI 预算，不把模拟模型成功报告为真实模型质量。

## 验证与回滚

使用真实临时文件系统/Git/子进程与受控外部适配器；行为风险覆盖权限、取消、重放、进程失败、状态损坏、失效证据、无遥测、发布幂等。先定向，再 impact/quality，最后完整 check。仅本 Task 路径原子提交；未验收 worktree 保留。实现可按 Task 提交回退；外部发布另按既有恢复合同。
