# PLAN-0032 待拍板决策简报（D3 / D4 / D5 / D7）

> 2026-11-25 整理。每个决策给出推荐方案、影响范围、备选与回退成本。拍板后回到 [PLAN-0032](PLAN-0032-upstream-vetta-alignment.md) 把决策结果写进对应行，并解开依赖阶段。

## D3 Plugin API 版本号

**背景**：本地 `apps/desktop/src/main/plugins/plugin-api-version.ts` 为 2.13.0；两边自 2.8.0 起各自编号；上游 2.9–2.11 是顶栏动作与 `useMeta`，与本地同号版本含义不同。

**推荐**：本地从 **2.14.0** 续编。每移植一项上游能力（顶栏动作 / `useMeta` / 其他）在 `plugin-api-version.ts` 注释和 `docs/plugins/` 版本说明中显式登记"本仓 2.x.y = 上游 2.x.y 能力 + 本地扩展"。

**影响范围**：P7 顶栏按钮组、P9 工作空间声明可用性。

**备选**：
- 跳到 3.0.0 一刀切：版本号断层大，现有插件兼容性检查会被惊吓。**不推荐**。
- 沿用 2.13.x 不升：上游能力进入时无版本可声明，插件无法判断能力。**不可行**。

**回退成本**：低。版本号是元数据，只影响能力声明，不影响协议线。

## D4 自动化无人值守 vs 权限分层

**背景**：上游 `0111d7cde` 把自动化数据模型重做为「运行会话策略」，无人值守运行**固定使用完全访问**；本地 [ADR-0132](../../docs/adr/0132-unattended-permission-tiers-on-scheduled-tasks.md) 已建立**无人值守权限分层**（PLAN-0012），并已交付 `permissionTiers` 与事件触发 `trigger` 字段（`SchedulerTaskFieldsView`）。

**推荐**：**只参照上游界面 + 会话策略交互，保留本地权限分层**。具体：
- 不引入「无人值守固定完全访问」。
- 不删除本地 `permissionTiers` / `trigger` 字段。
- 可移植的：间隔重复、运行会话策略 UI、侧栏会话组、删除绑定会话前提示。
- 移植前先核对本地是否已有「无人值守轮次不提供 ask_user_question」与「失败不记成功」的等价行为，没有则一并补齐。

**影响范围**：P9 自动化数据模型重做，需新 ADR 记录与上游 ADR-0127 的关系。

**备选**：
- 完全跟随上游：会破坏 ADR-0132 已交付的权限边界，违背「不削弱权限分层」硬约束。**不可行**。
- 完全不跟进上游自动化：放弃间隔重复、会话策略 UI 等用户价值。**不推荐**。

**回退成本**：中。数据模型一旦迁移，回退需保留旧字段读写路径。

## D5 工作空间边界

**背景**：上游 `d6f9906c4`（ADR-0155）新增工作空间分组、`ctrl+1..9` 切换；团队会话按 Team ID 归属。本地只有「Work/Coding 工作区模式」和 Allstar 两册；团队会话按 `16e40c8e6` 进入 Allstar 版块。

**推荐**：
- 工作空间只作用于**普通册**（非 Allstar、非团队）。
- **Allstar 不纳入**工作空间分组。
- 团队会话保持本地 `16e40c8e6` 的 Allstar 版块归属，**不**按上游 Team ID 归属。
- 命名统一：上游「工作空间」与本地「工作区模式」先做术语对齐，避免 UI 出现两个相似词。

**影响范围**：P9 工作空间分组、P7 顶栏（按工作空间过滤动作）。

**备选**：
- 完全跟随上游：与本地 Allstar 版块语义冲突，团队会话归属需迁移，用户已习惯的入口会变。**不推荐**。
- 不引入工作空间：放弃 `ctrl+1..9` 快速切换价值。**不推荐**。

**回退成本**：高。涉及会话归属变更，需迁移存量数据，需新 ADR。

## D7 用量页

**背景**：本地 `useUsageSeries.ts` 读云端 `/usage/me/series`（依赖登录 token，未登录不显示）。上游 `7ef3f6d20`（ADR-0156）**移除 vetta-serv，改用本机 app-monitor 数据**，按模型/小时统计 token，按月落盘；页面用 `chart.js ^4.5.0`。

**推荐**：
- **新增本机 app-monitor 用量页**，与云端用量**并存**（云端用量保留在账户页，本机用量在设置/用量）。
- **新增 chart.js ^4.5.0 依赖**：体积小（~80KB gzip）、tree-shakable、无 React 绑定必要（直接用 vanilla  API + ref）、上游已验证。
- 数据层先定义旧数据缺失时的读取路径（首次使用无 `months/<YYYY-MM>.json` 时返回空数组而非报错）。
- 核查团队会话成员的用量是否计入（如果团队会话走同一 app-monitor，应自然覆盖；如果走独立通道，需在文档说明）。

**影响范围**：P6 用量页，约 3.8k 行新增。

**备选**：
- 用 recharts / chartjs-2 替代：recharts 体积更大且 React 绑定冗余；chartjs-2 已 EOL。**不推荐**。
- 自写 SVG：体积小但维护成本高，无障碍/工具提示需重做。**不推荐**。
- 不做本机用量：未登录用户看不到任何使用数据。**不满足需求**。

**回退成本**：低。新增依赖+新增页面，不动存量逻辑，回退即删文件。
