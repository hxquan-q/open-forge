# Canvas、Browser、Terminal 支持情况核查

## 问题与范围

核查当前仓库实现是否支持 Canvas、Browser、Terminal，分别区分 Desktop 用户可见界面、Agent 工具路径、默认随包能力和可选扩展，并补充 CLI 与 Android 平台边界。这里的“应用”以 Electron Desktop 为主；仓库的研究记录规范将源码调研放在 `project/research/`，并要求记录事实来源、结论、代码锚点、置信度和下一步条件（`project/README.md:16-21`、`project/CONVENTIONS.md:198-210`、`project/research/TEMPLATE.md:1-29`）。

本报告只读核对本仓库当前源码、类型/配置、已有测试、官方产品文档，以及用户指定 11 个公开 GitHub 仓库的 README、相关源码/类型/API；未运行 Vetta 产品、测试或浏览器，也未 clone、执行、安装、登录或访问这些项目的 hosted demo。调查开始前工作区已有未提交改动，均予以保留。当前工作树中的项目工具策略接线也有预存改动，因此涉及工具可见性的结论按当前源码描述，不代表已发布版本。

## 当前结论

## 用户目标语义与参考项目

以下先记录用户澄清的口径；外部项目事实只按指定仓库当前 README、源码或 API 摘要，不把名称相似当成功能等同。

### 用户目标语义

- **Canvas**：类似 Cursor/GPT Canvas，在聊天中围绕 Agent 生成的 Markdown、HTML、代码等 artifact 直接迭代；内容需在同一对话工作流里渲染，并可指向其中一段内容继续提问或要求修改。这不是 `.vetd` 专用 UI 设计画布，也不要求一定是无限白板。
- **Browser**：一是用户在 Chromium 页面点选 UI 元素后，把该元素的 HTML、CSS、可访问性/周边上下文和裁剪截图作为 Agent 上下文；二是 Agent 获得一等 `browser_tab` 操作面，可用新鲜页面快照和可靠元素引用点击、填充、等待及读取结果。页面上的确认控件是网页操作；它本身不等同于对发布、付款、删除等不可逆外部动作的人类授权。

### Browser 一手资料

- **[Orca](https://github.com/stablyai/orca)**：README 的 Design Mode 宣称在真实 Chromium 点选元素，并把 HTML、CSS、裁剪截图送入 Agent prompt。源码确认它会提取 selector、HTML snippet、精选 computed styles、ARIA 名称/角色和元素 bounds；selector 以 ID/非哈希 class 为候选、检查唯一性并回退 `nth-of-type`。HTML 会去掉 `<script>`；主进程再过滤属性、净化 URL、遮盖疑似秘密字段并限制 payload 大小；截图按元素矩形单独裁切；选区 click 会 `preventDefault`/停止页面事件，不会顺手点击网页控件（[README](https://github.com/stablyai/orca/blob/main/README.md)、[`grab-guest-element-context-script.ts`](https://github.com/stablyai/orca/blob/main/src/main/browser/grab-guest-element-context-script.ts)、[`grab-guest-selection-scripts.ts`](https://github.com/stablyai/orca/blob/main/src/main/browser/grab-guest-selection-scripts.ts)、[`browser-grab-payload.ts`](https://github.com/stablyai/orca/blob/main/src/main/browser/browser-grab-payload.ts)、[`browser-grab-screenshot.ts`](https://github.com/stablyai/orca/blob/main/src/main/browser/browser-grab-screenshot.ts)）。
  - 代码显示两种 UI 路径：`copy` intent 把上下文文本或截图复制到剪贴板；`annotate` intent 收集评论/意图，并把包含 selector、HTML、computed styles 的 Markdown 送给 Agent。持久 annotation 类型明确把 screenshot 置为 null。因此代码验证了元素抓取、裁剪和 DOM/CSS annotation-to-Agent，但本次未从活动发送路径验证 README 所说“裁剪截图直接进 prompt”的完整链路（[`browser-page-grab-action.ts`](https://github.com/stablyai/orca/blob/main/src/renderer/src/components/browser-pane/annotate/browser-page-grab-action.ts)、[`browser-annotation-output.ts`](https://github.com/stablyai/orca/blob/main/src/renderer/src/components/browser-pane/annotate/browser-annotation-output.ts)、[`use-browser-page-annotation-send.ts`](https://github.com/stablyai/orca/blob/main/src/renderer/src/components/browser-pane/annotate/use-browser-page-annotation-send.ts)、[`browser-grab-types.ts`](https://github.com/stablyai/orca/blob/main/src/shared/browser-grab-types.ts)）。
  - Agent 操作网页是另一条 Browser Bridge：先 snapshot，再以 refs click/fill；不能把抓取选区本身当成点击页面控件（[`agent-browser-bridge-core-commands.ts`](https://github.com/stablyai/orca/blob/main/src/main/browser/agent-browser-bridge-core-commands.ts)、[`agent-browser-bridge-interaction-commands.ts`](https://github.com/stablyai/orca/blob/main/src/main/browser/agent-browser-bridge-interaction-commands.ts)）。
- **[browser-use/browser-use](https://github.com/browser-use/browser-use)**：提供独立的 Python/TypeScript browser agent/library 与 CLI。Python `DomService` 组合 CDP DOM 与 accessibility 数据形成页面树；`Element` 以当前 DOM 的 `backendNodeId` 定位并经 CDP geometry/input 点击，`Page` 另有截图和 JavaScript evaluate。这个 node/ref 依赖当前页面状态，导航或 DOM 重建后应重新 snapshot；低层 API 本身不是确认策略（[README](https://github.com/browser-use/browser-use/blob/main/README.md)、[`dom/service.py`](https://github.com/browser-use/browser-use/blob/main/browser_use/dom/service.py)、[`actor/element.py`](https://github.com/browser-use/browser-use/blob/main/browser_use/actor/element.py)、[`actor/page.py`](https://github.com/browser-use/browser-use/blob/main/browser_use/actor/page.py)）。这与 Vetta 使用的 `vercel-labs/agent-browser` 不是同一个上游项目。
- **[browserbase/stagehand](https://github.com/browserbase/stagehand)**：SDK 的 `observe()` 可把自然语言目标解析为真实 selector，再由调用方用 locator 填值；官方示例特意在代码里填入凭证，避免把凭证送给模型。`act()` 接受自然语言动作，README 描述了站点改版时的 self-healing；SDK 同时公开 locator click/fill。它是自动化 SDK，不自带 Vetta 式网页操作确认 UI；高影响动作门控由宿主/集成方决定（[README](https://github.com/browserbase/stagehand/blob/main/README.md)、[`stagehand.ts`](https://github.com/browserbase/stagehand/blob/main/packages/sdk-ts/src/stagehand.ts)、[`locator.ts`](https://github.com/browserbase/stagehand/blob/main/packages/sdk-ts/src/locator.ts)）。
- **[magnitudedev/browser-agent](https://github.com/magnitudedev/browser-agent)**：README 定位为 vision-first agent；Web action schema 直接接收屏幕 `x/y` 坐标点击、拖拽、滚动及键盘输入，而 BrowserAgent 的抽取路径也把页面 HTML 序列化为 Markdown 并附带截图。坐标方式适合无语义 DOM 的界面，但比快照 selector 更受 viewport、缩放和布局变化影响；这些 action 定义本身不提供事务确认门（[README](https://github.com/magnitudedev/browser-agent/blob/main/README.md)、[`webActions.ts`](https://github.com/magnitudedev/browser-agent/blob/main/packages/magnitude-core/src/actions/webActions.ts)、[`browserAgent.ts`](https://github.com/magnitudedev/browser-agent/blob/main/packages/magnitude-core/src/agent/browserAgent.ts)）。

## Canvas

**Desktop 当前有真实的 UI 设计画布，但它不满足用户澄清的通用对话 artifact Canvas 目标。** `vetta-ui-design` 同时出现在 development 与 production 的 `common` 插件清单中（`packages/plugins/tenants.json:4-37`）；插件清单声明了 Desktop UI 插槽、Agent 工具/Skill 和会话能力（`packages/plugins/presets/vetta-ui-design/plugin.json:16-60`）。用户可从侧栏“更多 → 设计”进入画廊，或在文件树右键 `.vetd` 目录打开画布；产品文档限定它用于独立设计/原型，不用于修改用户代码仓库里的真实前端实现（`apps/docs-site/content/docs/product/design.mdx:12-18,31-53,140-148`）。源码将画布注册为 Activity Tab，并在项目中发现 `.vetd` 后显示；右键动作也会直接打开该 Tab（`packages/plugins/presets/vetta-ui-design/src/index.tsx:108-154,216-241`）。`CanvasTab` 会读取设计稿、打开本地设计引擎，准备完成后渲染 `DesignCanvas`（`packages/plugins/presets/vetta-ui-design/src/canvas/CanvasTab.tsx:38-45,109-137,387-418`）。首次使用需准备设计引擎/依赖；官方说明约需 1–3 分钟，缺少托管 Node 时要先安装（`apps/docs-site/content/docs/product/design.mdx:50-53,142-148`）。

Agent 侧是插件专用工具：`vetd_create` 会创建 `.vetd` 并打开画布；`vetd_screenshot` 等工具仅针对当前 `.vetd` 设计（`packages/plugins/presets/vetta-ui-design/src/tools.ts:113-124,188-215`）。除创建入口外，`vetd_status`、`vetd_install`、`vetd_notes`、`vetd_history`、`vetd_restore`、`vetd_export` 等由工作区设计稿/画布状态门控（`packages/plugins/presets/vetta-ui-design/src/vetd/tool-gate.ts:6-24`）；测试覆盖普通代码工作区关闭设计工具、有 `.vetd` 或画布打开时放行的路径（`packages/plugins/presets/vetta-ui-design/test/tool-gate.test.ts:62-99`）。因此 `.vetd` 是有真实 UI 与 Agent 操作能力的设计 Canvas，但不应计为“在聊天中围绕生成 Markdown/HTML artifact 迭代”的目标支持；本次未发现通用 artifact Canvas 工具或与文件预览绑定的 Agent artifact 状态。

**`.vetd` 已有一个范围受限的选区追问闭环：**在设计 frame 中点选 DOM 元素后，bridge 产生 `tag`、`domPath`、`classes`、截断文本、矩形和源码位置；元素旁的 `SelectionAskBadge` 提供输入框，提交后保存为 element-anchor note。Agent 空闲时由 handoff 自动派发提示，Agent 再调用 `vetd_notes` 读取锚点与标注后的 frame 截图（`packages/plugins/presets/vetta-ui-design/src/canvas/bridge-client.ts:8-15`、`packages/plugins/presets/vetta-ui-design/src/canvas/SelectionAskBadge.tsx:4-13,93-108,141-154`、`packages/plugins/presets/vetta-ui-design/src/notes/handoff.ts:104-123`、`packages/plugins/presets/vetta-ui-design/src/notes/types.ts:18-25`）。这证明设计画布内可直接围绕选中元素交互，但不是通用 Browser 选区：持久锚点不含完整 `outerHTML`/computed CSS，图像是带标注的 frame 截图而非所选元素裁剪图，Agent 通过后续工具读取而非点击时直接把整包上下文塞入 prompt。

“Canvas”若指无限白板，仓库另有 Cowart：它注册独立 Activity Tab 和 `open_cowart_canvas` Agent 工具，面板加载 tldraw 画布（`packages/plugins/externals/cowart-vetta/src/index.tsx:30-67`、`packages/plugins/externals/cowart-vetta/src/CanvasPanel.tsx:6-19,75-85`）。它位于 `externals/`，自身说明明确标为需用户构建/安装的外置插件；它没有出现在默认 production tenant 的插件数组中（`packages/plugins/externals/cowart-vetta/README.md:5-9`、`packages/plugins/tenants.json:23-37`），所以不是 Desktop 默认自带白板。

**文档与当前 UI 有一处差异：**设计文档说可以从画布“导出分享”（`apps/docs-site/content/docs/product/design.mdx:105-113`），但 `CanvasTab` 当前把画布工具栏的“导出分享”入口显式关闭（`packages/plugins/presets/vetta-ui-design/src/canvas/CanvasTab.tsx:31-32,335-344`）。画廊卡片右键导出分享仍有实现（`packages/plugins/presets/vetta-ui-design/src/gallery/CardContextMenu.tsx:116-128`、`packages/plugins/presets/vetta-ui-design/src/gallery/GalleryView.tsx:193-208,397-400`）；Agent 的 `vetd_export` 是导出 PDF/PNG，不是分享包（`packages/plugins/presets/vetta-ui-design/src/materials/export-tool.ts:1-7,68-91`）。所以“画布内的分享按钮”不能按文档描述判定为当前可用。

**渲染复用点与 artifact loop 的差别：**聊天消息由 `MarkdownContent` 流式渲染，Markdown 文件预览由 `MarkdownPreviewView` 渲染；HTML 文件预览由 `HtmlPreviewView` 将内容放入 iframe（`sandbox="allow-scripts allow-same-origin allow-popups allow-forms"`）。这些是消息/文件预览；本次核对未发现它们与可选取内容并继续向 Agent 迭代的独立 artifact 状态相连（`packages/theme-ui/src/markdown/MarkdownContent.tsx:124-134`、`packages/theme-ui/src/activity/MarkdownPreviewView.tsx:126-216`、`packages/theme-ui/src/activity/HtmlPreviewView.tsx:80-132`）。

相邻但未落地的架构工作：`TASK-0027` 当前为 `ready`，目标是通过 plugin contribution 为 Artifact descriptor 注册 Renderer type/schema，并在资源授权后渲染；已完成的 `TASK-0015` 实现的是 Task/Artifact descriptor 持久化及 Task Activity Panel 列表，不是通用聊天 Canvas。当前 `ArtifactDescriptor` 仅含 `kind`、`uri`、`contentType`、可选 `rendererType` 等路由/生命周期元数据（`packages/runtime-core/src/task/contracts.ts:123-145`），因此可把 `TASK-0027` 视为候选复用入口，但不能据此声称 Renderer Registry 已实现（`project/tasks/TASK-0027-plugin-artifact-renderer-registry.md:1-45`、`project/tasks/TASK-0015-task-artifact-vertical-slice.md:24-34,46-53,91-105`）。

## Browser

**Browser 名称对应四种不同调用面；WebView、Agent CLI、`ctx.browser` 与 MCP 不是同一 session 或能力。**

1. **内置浏览器面板（手动浏览/预览）**：Activity Panel 的 `browser` Tab 在工作区已有 URL 时显示（`apps/desktop/src/renderer/domains/activity-panel/builtins/browser-tab.tsx:15-33`）；视图提供地址栏、前进/后退、刷新和 Electron `<webview>`，cookie 分区为 `persist:vetta-browser`（`packages/theme-ui/src/activity/BrowserPanelView.tsx:97-140`、`apps/desktop/src/renderer/domains/activity-panel/hooks/useBrowserPanelModel.ts:12-14,149-175`）。从 Markdown 链接打开 URL 会切到该 Tab，URL 状态按 workspace 保存在内存（`apps/desktop/src/renderer/shared/store/browser-atoms.ts:5-9,21-32`）。它是手动浏览面板；本次未发现 Orca 式元素点选、HTML/CSS 抽取和选区截图附加到 Agent 的 UI/IPC 路径。
2. **Browser Use（Agent 自动化）**：`browser` 系统插件随 production tenant 发布（`packages/plugins/tenants.json:31-36`）。Agent 使用 `browser-use` Skill 经 shell 调用 Vetta 管理的 `vercel-labs/agent-browser` CLI；Skill 明确写着“不寻找专用 Browser Tool”，并要求每个 Agent task 使用自己的 `VETTA_AGENT_SESSION_ID`、`--pin-tab`、先 snapshot 再用 `@eN` refs click/fill，页面变化后重新 snapshot（`packages/plugins/presets/browser/plugin.json:14-25`、`packages/plugins/presets/browser/agent/skills/browser-use/SKILL.md:8-43`）。它能完成网页交互，但不是原生 `browser_tab` Tool；要求 full-access shell，且 Skill 要求把网页内容视为不可信数据、对 publish/submit/send/delete/purchase 等不可逆动作先取得用户确认（同文件 `:26-33,77-83`）。该 CLI session 与 WebView、`ctx.browser` session 不共享（`packages/plugins/presets/browser/README.md:9-20`）。
3. **Desktop 的 `ctx.browser` 插件 API / Foundation Capability**：`open()` 只打开 Browser Panel，不返回网页内容或授予交互权限；其它公共方法提供 managed session、navigate、snapshot、readText、screenshot 和 `act`。`act` 的 click/fill 等结构化动作要求 `browser.interact`，并使用 snapshot revision 拒绝过期 ref（`docs/plugin/browser.md:3-5,52-78`、`apps/desktop/src/renderer/domains/plugins/runtime/plugin-host-apis.ts:170-227`、`apps/desktop/src/main/browser-automation/browser-automation-service.ts:239-304`）。宿主在导航前/操作后复核 `allowedHosts`，越界会关闭 session；公共 API 不提供任意 JS、Cookie/token 导出（同文件 `:239-304`、`docs/plugin/browser.md:35-78`）。但当前 Browser 系统插件 manifest 只声明 `browser.read`、`browser.runtime.manage`，未声明 `browser.interact`；插件 UI 只使用 runtime status/install，因此这条 API 是可复用的插件能力，不是当前 Agent 的直接工具（`packages/plugins/presets/browser/plugin.json:14-25`、`packages/plugins/presets/browser/src/index.tsx:22-56`）。
4. **用户可配置 MCP**：MCP 设置可新增自定义 stdio/HTTP server，Agent 会聚合全局、项目、插件三源工具（`apps/desktop/src/renderer/domains/settings/components/McpServerForm.tsx:42-46,64-80,149-162,200-216`、`docs/plugin/mcp.md:7-34`）。表单里的 `@playwright/mcp@latest` 只是自定义 stdio 的示例占位，不代表随包安装的 Browser MCP；用户可另行配置第三方服务，其工具面与安全策略由该 server/配置决定，表单也允许设置 `autoApproveTools`（`apps/desktop/src/renderer/domains/settings/components/McpServerForm.tsx:91-96`；协议配置字段见 `docs/plugin/mcp.md:90-92`）。当前内置 MCP 预设是 Canva、Slack、Gmail、Google Calendar、Google Drive，没有浏览器自动化预设（`apps/desktop/src/renderer/domains/settings/components/McpServerForm.tsx:149-162`、`apps/desktop/src/renderer/domains/settings/mcp/builtin-mcp-presets.ts:84-192`）。`@vetta/runtime-mcp/browser` 也只是 MCP App Attachment/媒体准入模块，不是浏览器控制 Runtime（`packages/runtime-mcp/README.md:25-27`）；外部 MCP 的 session、域名限制和确认策略不等同于 Desktop WebView 或 `ctx.browser`。

运行时准备也不是“装插件即就绪”：Desktop 锁定并检查 `agent-browser` 0.34.0；CLI 缺失/过旧时安装到 Vetta 私有 npm prefix，健康检查确认缺 Chrome 后才下载 Chrome for Testing。相应状态与安装分支有定向测试，但本次未运行（`apps/desktop/src/main/browser-automation/browser-runtime-manager.ts:5,30-41,59-98`、`apps/desktop/src/main/browser-automation/browser-runtime-manager.test.ts:7-68`、`packages/plugins/presets/browser/agent/skills/browser-use/SKILL.md:12-24`、`apps/docs-site/content/docs/product/browser.mdx:34-57`）。

所以，当前 Agent 可以通过 shell CLI snapshot/click/fill 网页；但 Vetta 没有 `browser_tab` 一等工具，也没有 Orca 式 DOM/CSS/截图上下文选择流程。`ctx.browser` 是一等的宿主插件 API，却刻意未作为 Agent 工具注册：ADR-0090 明确选择 Browser Skill + shell CLI，并取消浏览器专用 `browser_operate` Tool（`docs/adr/0090-agent-browser-cli-uses-agent-owned-sessions.md:17-32`）。

## Terminal

**Desktop 有独立的交互终端面板。** `terminal` 是内置 Bottom Panel，允许多个实例，但本地会话要求 local PTY（`apps/desktop/src/renderer/domains/bottom-panel/builtins/terminal-panel.tsx:4-13`）。`TerminalSurface` 创建 xterm、经 `window.vetta.terminal` IPC 开 PTY、双向传递输入和输出（`apps/desktop/src/renderer/domains/bottom-panel/terminal/TerminalSurface.tsx:37-57,65-85,146-194`）。主进程懒加载 `@lydell/node-pty` 并探测可用性；缺失时本地终端不可用而不阻止应用启动，Bottom Panel 会隐藏需要本地 PTY 的入口（`apps/desktop/src/main/terminal/local-pty-backend.ts:16-50,137-150`、`apps/desktop/src/renderer/domains/bottom-panel/registry/useBottomPanelDefinitions.tsx:94-105`）。交互 shell 默认按平台选择，支持 Windows PowerShell/cmd 候选与 POSIX `$SHELL`/zsh/bash/sh 候选，也可传自定义 shell 路径（`apps/desktop/src/main/terminal/resolve-terminal-shell.ts:17-29,55-83`）。

远程项目 `ssh://` 的 Terminal 命令走远端连接，不会误落到本机；有 SSH helper 时使用可调整尺寸的 PTY，helper 不可用时退化为无 resize 的 `ssh -tt`（`apps/desktop/src/main/terminal/terminal-service.ts:71-96`、`apps/desktop/src/main/terminal/remote-pty-backend.ts:7-12,14-30`）。测试明确覆盖远程不可达时不调用本地 backend（`apps/desktop/src/main/terminal/terminal-service.test.ts:192-222`）。

**Agent 的命令工具不是上述交互面板。** Desktop Runtime 通过 Node coding environment 装配本地或 SSH Coding Tools（`packages/runtime-desktop/src/coding-agent-tool-environment.ts:38-70,80-121`）；CLI host 也装配 Node tool environment（`apps/cli-host/src/rpc/runtime-host/cli-tool-environment.ts:29-45`）。Runtime Node 在 Windows 注册 `shell`，其他平台注册 `bash`（`packages/runtime-node/src/coding/host/tool-environment.ts:40-65`、`packages/runtime-node/src/coding/node-tool-environment.ts:91-124`；`bash` 实现名见 `packages/runtime-node/src/coding/tools/bash/bash-tool.ts:15-21`）。CLI 是终端宿主并提供 Agent 命令入口，但 `apps/cli-host` 自身不拥有 UI Terminal 面板（`apps/cli-host/README.md:3-12,28-33`）。当前 Desktop 工作树的 Agent 工具目录可能受项目策略收紧：`.vetta/policies/tools.json` 的 `denyTools` 可拒绝任意工具名，Desktop 会在解析 session config 时应用它（`packages/coding-agent/src/projects/project-tool-policy.ts:7-21,32-51`、`apps/desktop/src/main/conversations/resolve-session-config.ts:79-91`）。

## 被否决的解读、失效条件与置信度

- 不以产品名称或宣传文案单独判定功能：Vetta 当前 Canvas/Browser 结论锚定源码、manifest、权限和运行时 API；外部比较只取用户指定仓库的一手 README/代码/API。
- 不把 `.vetd` 设计画布、Cowart 白板、Markdown/HTML 文件预览合并成通用对话 artifact Canvas；它们分别是设计稿、空间白板和文件呈现表面。
- 不把 Browser WebView、`agent-browser` shell CLI、插件 `ctx.browser` 和用户可配 MCP 合并成一个 Agent Tool 或 session；Browser WebView/CLI/API 的宿主、状态和权限各自不同。
- 高置信结论限于当前源码与打包清单：Desktop 已有 `.vetd` 设计画布、Markdown/HTML 呈现、手动 WebView、Agent shell 浏览器自动化及插件 Browser Capability；但用户澄清的通用 Canvas 未发现，Browser 目标仅部分覆盖。CLI/Android“没有原生 Canvas/Browser/PTY 面板”仍是本次检查范围内的中等置信度结论，不等同于不能自装工具或远程操作。
- `langchain-ai/open-canvas` 已归档；`CopilotKit/open-gemini-canvas` README 指向 CopilotKit monorepo 的迁移位置。其余链接按本次读取的 GitHub `main` README/源码记录，未来 upstream 变更会使引用结论失效。
- 工作区现有改动包含项目工具策略的导出/接线；因此 `denyTools` 对 Agent 工具可见性的描述反映当前工作树，不能据此宣称其已包含在某个正式发布版本。后续若修改 `packages/plugins/tenants.json`、对应 preset/host Composition、Browser Capability/Agent Tool 接线、Native PTY 打包或项目 tool policy，应重新核查此报告中的分发与可用性结论。
