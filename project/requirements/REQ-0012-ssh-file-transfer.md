# SSH 远程项目文件传输（上传/下载）

## 用户问题与结果

远程项目的文件栏能浏览、编辑并保存远端文件（`ssh://` URI 经 `remote-filesystem.ts` 分流），但没有「本机 ↔ 远程设备」的文件传输入口：用户无法把本地文件放进远程项目、也无法把远端文件取回本机，二进制大文件更是完全不可达。结果：文件栏对远程项目提供上传（拖拽/菜单）与下载（菜单）能力，带进度、可取消，传输走既有 SSH 传输层。

## 范围

- 文件树上下文菜单：远程条目「下载到本机…」；远程目录「上传文件…/上传文件夹…」。
- 拖拽上传：从 OS 文件管理器把文件/文件夹拖到远程项目的文件树上即上传。
- 传输队列：多任务排队、并发上限、字节级进度、取消、失败原因展示；单文件与文件夹（递归展开为多条目）。
- 传输通道复用既有 SSH 连接层（ControlMaster / ssh2 多路复用），不新增认证或主机密钥路径。

## 不做什么

- 不引入外部传输引擎（SFTPGo 是服务端方向相反；aria2 无上传能力），不新增 SFTP 协议子系统——传输通道选择与理由记录在 TASK-0240。
- 不做断点续传、限速、传输后 checksum 复验（SSH 传输层 MAC 已保证完整性）。
- 不向 Agent 工具暴露传输能力；不改动本地↔本地的既有拖放/复制机制。
- 不改动 helper 协议（保持 1.1.0）；helper 加速留待后续。

## Given / When / Then

- Given 已连接的远程项目，When 在文件树右键远端文件选「下载到本机…」并选目录，Then 本机出现字节一致的文件，进度面板显示完成。
- Given 远程项目文件树，When 从 OS 拖一个文件到远端目录节点，Then 若同名先询问冲突策略，随后远端出现内容一致的文件，目录监听刷新。
- Given 一个正在上传的大文件，When 用户取消，Then 远端目标文件保持原样、无临时文件覆盖目标，面板显示已取消。
- Given 传输中网络断开，Then 面板显示失败且远端结果按不可知处理，半截数据不得替换目标文件。

## 必须保持的不变量

- 远端路径授权边界（`assertRemotePathWithinProject`）对传输目标同样生效，`..` 与项目根外路径拒绝。
- 失败三分类语义：传输层故障 = unverifiable，远端非零 = exited；不得把「远端说没有」与「问不到」合并。
- 取消必须显式终止远端进程组/通道（ADR-0124：无 pty 通道关闭不会杀远端进程），且原子写校验拦截半截落盘。
- 主机密钥确认、askpass、连接复用等既有安全与生命周期路径零改动。

## 验收标准

- 单文件上传/下载在真实连接上字节一致；取消与断链场景目标文件不被破坏。
- 文件夹传输按相对结构重建（本地或远端两侧 mkdir 补齐）。
- 进度、取消、失败原因对用户可见；i18n 覆盖全部新文案。
- 定向测试（传输原语 + 服务队列 + UI 接线）与 `test:impact`、完整 `check` 通过。

## 风险

- 通道流式写入无背压信号会放大内存占用——通道端口需提供 drain 感知写（见 TASK-0240 设计）。
- 上传取消存在「EOF 也会让远端 cat 完成」的竞态，必须以远端字节数校验拦截 mv。
