# Windows 电脑操作

## 用户问题与结果

用户希望 AI 直接操作本机 Windows 全局桌面，而不是先选择已存在的应用窗口。用户开启电脑操作并授权当前对话后，AI 应能观察整个桌面，通过全局键鼠打开尚未运行的应用，再继续完成任务。页面保留开启、授权当前对话、暂停和停止；不要求窗口选择、观察/后台/前台权限档或逐动作审批。**安装 Vetta 后即可使用，不要求另装或配置 Python/winhands。**

来源：工作区 `D:/Coding/WorkSpace/Vetta/computer-use-handoff.md`；2026-11-10 用户确认开箱可用；2026-11-11 用户明确要求全局桌面操作优先，先实现可用能力，后续再演进。

## 范围

- Windows 首版，能力默认关闭；开启后由用户授权当前对话，授权不跨应用重启沿用。
- 操作面是当前 Windows 虚拟桌面：观察完整桌面截图，点击、按键、输入文字和滚动均可作用于任意当前桌面区域；不绑定已发现窗口，也不限制应用或终端。
- 模型可通过桌面 UI（如开始菜单/运行对话框）启动尚未打开的应用，再继续观察和操作；不需要先存在该应用的窗口。
- 操作调用不做逐动作风险审批，不按 observe/background/foreground 分级，也不因检测到用户输入自动接管或拒绝；用户通过明确的暂停/停止入口控制 AI。
- 保留当前对话的控制归属，避免多个模型回合同时驱动同一桌面；暂停/停止等待操作结束并释放持有输入后才完成。
- Vetta 自身隐藏/唤回与置顶独立控制；托盘和系统快捷键提供隐藏后的暂停/停止/唤回入口。
- 兼容恢复旧版本记录的已隐藏窗口；全局操作新路径不再隐藏目标应用或要求按窗口恢复。
- 随应用分发兼容执行后端和许可，不依赖开发机绝对路径或系统 Python；非 Windows 提示不支持。

## 不做什么

不引入虚拟机、独立桌面或远程 relay；不替换 browser_tab；不声称功能具备 OS 沙箱或系统级隔离。当前实现不另加进程启动 API，启动应用由 AI 使用全局桌面输入完成。不操作用户真实桌面/Provider 验证，不修改现有 winhands 或用户级配置，不发布或推送。

## Given / When / Then

1. Given 新装 Windows Vetta 且无 Python/winhands，When 开启电脑操作并授权当前对话，Then 使用随包后端，不要求选择应用窗口或额外配置运行环境。
2. Given AI 授权已生效且目标应用尚未运行，When AI 观察桌面并通过全局键鼠打开应用，Then 返回全桌面图像并能继续操作新出现的窗口；不存在窗口选择前置条件。
3. Given 全局电脑操作正在执行，When 用户暂停或停止，Then 不接受新动作；当前动作结束/取消后释放所有持有输入，停止回执确认后功能进入暂停或关闭状态。
4. Given 用户隐藏 Vetta 主窗口，When 通过托盘或配置快捷键操作，Then 可唤回 Vetta 或暂停/停止全局操作；Vetta 显隐与 AI 授权状态分离。
5. Given 旧版本留下已隐藏窗口恢复记录，When 更新后用户停止操作或主动找回，Then 能继续恢复这些旧记录；新版本全局操作不产生新的目标窗口隐藏记录。

## 必须保持与验收

保留 browser_tab、现有 Agent 角色/工具结果图片/错误/取消/usage 合同及包依赖方向。模型工具按具体动作声明顶层 object 参数，适配 OpenAI Responses；外部模型参数仍在工具入口结构校验，错误不得变成无效输入的静默成功。快捷键可配置；用户可通过明确暂停/停止恢复控制权。

工程验收包括代表性连续流程（授权→观察桌面→打开应用→输入/点击→暂停/停止）、工具 Schema 与 IPC 合同、进程取消及输入释放、旧窗口恢复兼容、组件交互、离线资源打包/后端完整性检查与根完整 check。真实桌面兼容性和真实模型效果单列未验证，人工接受后才能关闭需求。

## 风险与失效条件

全局截图和键鼠可作用于当前桌面中的任意应用；物理桌面上正在进行的用户操作可能与 AI 输入交错，用户应使用暂停/停止控制交接。截图或输入后端失败必须明确返回错误；进程强停不能虚构已完成副作用回滚。依赖分发必须带许可，构建必须在后端缺失时失败。旧版本恢复记录需保留到找回完成，不承诺系统崩溃即时恢复。
