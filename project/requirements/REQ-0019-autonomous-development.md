# 任务合同驱动的自主研发全流程

## 用户问题与结果

用户要求完整实施自主研发方案，不以首批试点作为交付终点。开发目标进入现有 REQ/PLAN/TASK 后，工具无关的执行系统负责调度、隔离实现、独立评审、可信验证、授权集成、发布准备、受控灰度和经验回流。

## 范围

- 复用 Task 状态、Worktree、Bun 质量门禁、发布说明碎片和现有发布流程。
- 结构校验的策略、运行合同、身份、证据和闸门；单一调度者、持久化租约代次、幂等与恢复。
- 可替换执行器、独立评审、隔离环境、停滞/循环熔断、用量记账；不设置金额硬上限。
- CI/崩溃/依赖等信号去重、每日复盘、不同日期重复教训晋升候选和每日决策摘要。
- UI 规则与行为验证接线、集成后证据失效判定、候选与稳定发布条件、监控缺失暂停。
- 完整命令行流程和故障注入测试；真实执行、部署和发布条件逐项记录。

## 不做什么

不更改产品运行时 Agent 协议，不叠加第二套 Task 状态机，不自动扩展现有发布/真实 Provider/生产访问权限，不使用真实用户状态测试。用户文件中的历史“已授权”文字不作为新的操作授权。

## Given / When / Then

- Given ready Task 和有效策略，When 自主运行，Then 从真实 Task 入口领取、执行、评审、验证，只有合同与权限同时满足才进入集成。
- Given 旧 Worker、重复事件、过期证据或缺失监控，When 恢复或晋级，Then 不重复集成、不接受过期结果、不扩大灰度，并留下可恢复记录。
- Given 不同日期独立失败，When 每日复盘，Then 形成带证据的晋升候选；修改守卫仍遵循规则治理。
- Given 外部证书/账号/CI 配额或发布授权缺失，When 完整交付审计，Then 如实保留未完成项，不用模拟验证冒充真实 L4。

## 必须保持

角色/工具/错误/取消/usage/stop 语义、包边界、用户改动归属、main→origin/dev→origin/main 授权边界与检查强度保持。缺失身份是 unknown，缺失验证不是通过。

## 验收标准

PLAN-0019 的逐项审计矩阵均有实际实现和对应证据；本地软件流程、真实执行条件和生产发布分别验收。单元测试通过不能替代后两者。

## 风险与失效条件

CLI 能力和版本、远端 CI 可用性、签名及监控由外部状态决定；运行器必须拒绝不完整权限和不可信证据。TASK-0321 的触发策略已在实施基线，继续保留；不覆盖其他会话的工作。
