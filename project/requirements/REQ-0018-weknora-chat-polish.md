# 智能客服页面打磨：收起 / 右键删除 / 后台思考

## 用户问题

智能客服首版（REQ-0017）交付后暴露三个使用痛点：左侧历史会话栏固定占 256px，窗口小或不需要历史时碍事；历史会话只能越攒越多，没有删除入口；一个对话还在生成回答时切到别的对话，界面上等于把那个回答丢了——虽然服务端仍在跑，但看不到进度、切回也接不上。

## 用户结果

历史会话栏可一键收起（整栏隐藏、状态跨重启记住）；右键历史会话可删除（先确认、明示不可恢复，删除作用于 WeKnora 服务器）；回答生成中切走对话后**后台继续生成**，列表行亮「思考中」指示，切回实时续显，多对话可并行提问，后台完成仅静默刷新列表。

## 范围

1. **侧栏收起**（A）：页头开关 + localStorage 持久化；纯渲染层，不经 view model、不进主进程。
2. **右键删除**（B）：`DELETE /api/v1/sessions/{id}` 四层链路（主进程 HTTP → IPC → preload → 渲染层）；右键菜单（仅删除项、可扩展结构）+ 确认弹窗 + 失败内联重试；删除当前打开的会话回到「新对话」空态；生成中的会话禁删。
3. **后台思考**（C）：流式模型从「单当前会话」重构为「按会话路由」——流归属表 + 每会话缓冲 + 纯函数路由模块；取消仅对当前会话生效；后台终态合并去抖后静默重拉列表。
4. **文案**：全部走 i18n，中文为基准并维护英文镜像。

**明确的边界**：

- **不改 WeKnora 侧任何配置**。删除是数据面调用（与建会话同类），调用方 Key 需具备对话能力（chat）。
- 删除为软删但平台无任何用户可见恢复入口，且会连带清理该会话的聊天历史知识库条目——对用户**等效不可恢复**，确认弹窗如实告知。
- 后台流**不提供取消入口**（跑到自然终态）；后台完成**无弹窗/通知**（用户裁定静默）。
- 首版打磨不含：批量删除、清空消息（平台接口存在但本需求明确不用不暴露）。

## Given / When / Then

- **Given** 会话 A 回答生成中；**When** 切到会话 B 并提问；**Then** A 在后台继续生成（列表行亮「思考中」），B 正常提问与回答，两路互不串台；切回 A 立即看到已生成部分并继续实时刷新。
- **Given** 任意历史会话；**When** 右键选择「删除会话」并确认；**Then** 该会话从 WeKnora 删除、列表刷新；若它是当前打开的会话，聊天区回到全新空白对话。
- **Given** 会话正在生成回答；**When** 右键该会话；**Then**「删除会话」置灰不可点。
- **Given** 已收起侧栏并重启应用；**Then** 侧栏保持收起；首次使用默认展开。

## 验收

工程侧：全部验收标准见 `docs/devflow/weknora-chat-polish/01-spec.md`（22 条）；先行实测（T00）已验证删除链路（201/200/列表消失/404 形态）与并发双流互不串台。人工侧：待实机预览与部署环境确认。
