# 「Allstar 自主开发」功能版块

## 问题

桌面端的工作区档位（文档与研究 / 代码）此前藏在新会话选项行的分段切换器里，面向不懂开发的
实施用户不可发现，也无法承载开发专属能力（项目管理、环境安装、流水线驾驶舱、内置 git）。

## 用户结果

- 用户从侧边栏「更多」之后的「Allstar自主开发」入口进入开发版块；普通「新会话」一律默认
  「文档与研究」档，代码模式只能经该入口进入（已交付，TASK-0422）。
- 最终态：入口升级为功能版块——自带项目管理、会话管理、各项目单独配置与开发环境配置/
  安装；allstar-coding 流水线 agent 集合体整体并入版块（预置插件形态退役）；内置面向
  实施用户的 git 能力（拉取/推送/跟踪，自带运行时、不依赖系统 git）与数据库 MCP。

## 范围

- 版块入口与档位语义（M0，已交付）；
- 版块壳：专属路由、项目空间、会话管理、项目级配置（M1）；
- 流水线并入宿主与驾驶舱（M2）；
- 内置便携 git + git MCP（M3-core）与数据库 MCP、环境声明/缺项安装（M4'，12 月）。

## 不做

- 不保留独立的 allstar-coding 预置插件入口（并入后退役）；
- 不做 push/tag 等发布动作的自动化（发布始终需用户授权）；
- 环境勘探环节的触发位置暂缓决策（并非每次流水线启动都对应项目，见 PLAN-0027 待定池）。

## Given / When / Then

- Given 任意项目档位为默认，When 用户点击侧边栏「Allstar自主开发」，Then 落该项目新会话页
  且按代码档创建会话（工具面含终端），入口在开发态高亮；
- When 用户经「新会话」类入口（侧栏、会话页头、项目详情页）新建会话，Then 项目档位回落
  文档与研究，会话按 work 档创建；
- Given 已打开研究会话，When 用户进入开发版块后切回该会话，Then 右栏布局保持工作台
  （跟随会话创建时固化的 capabilityProfile，不随项目档位联动）。

## 必须保持的不变量

- 档位是项目级偏好，只在新会话创建时决定解释模式与工具面，不改变已开会话；
- 存量 `vetta-workspace-mode` 记录只有 work 值（旧默认 coding 从不落盘），默认档翻转为
  work 后无需数据迁移；
- 代码模式的进入入口有且只有侧边栏版块入口一处（由 agent-mode-entry-points 结构合同守住）；
- **LLM 行为热追踪（AI 命令投屏/文件跟随/页签跟随）是 code 模式独有**（2026-10-30 用户
  决策，TASK-0434）：非 coding 档单会话不写全局活动，非 coding 挂载点不跟随、不显示 AI
  终端回放页签；团队会话天生 coding 档维持热追踪。行为取舍：work 会话的写类/命令活动
  不再驱动右栏跟随与投屏（发布说明须写明）；
- 内置 MCP 面向插件/MCP 不可信边界：最小权限声明、结构校验、写操作过审批。

## 验收标准

- M0（已验收）：TASK-0422 交付记录与 2026-10-26 用户 dev 实机走查；
- M1+：见 PLAN-0027 各阶段验收信号与对应实施 Task。

## 风险

- M2 preset 退役涉及存量已装用户的升级兼容（state.md / 存档）；
- 便携 git 制品的许可与受控校验链（参照 Windows 沙盒制品校验先例）；
- 月内时间线依赖用户评审不过夜的排期前提（PLAN-0027）。
