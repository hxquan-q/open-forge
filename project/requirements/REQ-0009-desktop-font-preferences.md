# Desktop 外观字体偏好

## 用户问题

用户希望在外观设置中选择不同字体；先完成同类产品与字体许可调研，随后授权建立 Task 并在独立工作树完成实现。

## 用户结果

在保留默认外观的前提下，按阅读与代码辨识需求选择字体，而不必修改配置或系统全局字体。调研结论见 [RESEARCH-0020](../research/RESEARCH-0020-desktop-font-preferences-and-licenses.md)；用户已授权按本机字体优先的边界实施，具体工作见 TASK-0181。

## 范围

源码、三类桌面产品与字体许可调研已完成；本轮实施范围：

- 外观设置分为“界面字体”与“代码字体”，终端首版跟随代码字体。
- 界面字体覆盖主窗口宿主 UI、对话正文与输入；代码字体覆盖宿主代码、Diff、预览及终端，保留等宽对齐。
- 提供默认选项、本机字体选择、中英混排预览与恢复默认；偏好即时生效、重启保留，不随主题切换丢失。
- 只选择本机字体，不随包内置字体。Monoid 可选 MIT，主流 OFL 字体不能误标为 MIT；后续分发字库另行确定资产与授权。

## 不做什么

- 不安装/打包字体，不新增依赖或 IPC，不启动真实 Desktop；提交与集成遵循 Task 工作流，稳定发布未授权。
- 首版不做字体商店、远程字体下载、任意字体文件导入、跨机同步、聊天第三套字体、独立终端字体以及字号/行高/连字开关。
- 不承诺改变操作系统原生菜单、外部网页、插件 iframe 或用户产物的字体。
- MIT 暂按许可证理解，不按麻省理工学院品牌字体理解；不将“仅 MIT”推定为用户已确认的硬要求。

## Given / When / Then

以下为功能验收合同，实际实现与验证状态以 TASK-0181 为准：

1. Given 默认用户，When 打开外观设置并预览另一字体，Then 生效范围明确，现有默认可恢复，中文与英文预览可读。
2. Given 用户改变界面字体，When 返回对话，Then 正文与输入按偏好显示，代码仍保持等宽。
3. Given 已打开代码预览、Diff 与终端，When 改变代码字体，Then 声明的宿主代码表面与终端响应，终端会话和已有输出不丢失。
4. Given 已保存字体，When 切换明暗/颜色主题或重启，Then 偏好保持；恢复默认后回到现行默认外观。
5. Given 字体缺失、偏好无效或列表加载失败，When 打开设置或启动，Then 安全回退并可重新选择，不崩溃、不阻塞主要使用流程。

## 必须保持

- 默认外观和已有主题、国际化、键盘可访问性；中文、符号与代码等宽回退。
- 终端会话、连接与输出生命周期；字体变化不触发新 Shell 会话。
- 字体是本机展示偏好，不改变 Agent 消息、工具、权限或模型配置。
- 本机字体列表不上传；字体枚举失败可恢复；引用系统字体不等于获准复制其文件。
- 第三方字体按实际资产与版本保留许可；OFL 字体不冒充 MIT，包装依赖许可证不替代字体许可证。

## 验收标准

### 已完成研究

- [x] 以实际源码确认当前字体入口、主题覆盖行为与终端适配风险。
- [x] 给出至少三个同类/相邻产品的第一方做法，区分当前文档与开发分支证据。
- [x] 核实可选 MIT、复合许可与 OFL 的差异，并提出中文回退与分发建议。
- [x] 明确事实、推荐、未验证项与后续触发条件；研究完成不自动授权实现。

### 后续产品

由 TASK-0181 验证完整“选择 → 返回使用 → 切主题 → 重启 → 恢复默认”流程与活动终端、缺字体失败路径；尚未进行功能验收，不关闭本需求。

## 风险与失效条件

本机字体枚举的系统差异、中文覆盖、主题优先级、终端字符测量、内置字库体积和许可证变化。若需要内置字体，应先处理与现有系统字体设计基线的取舍。若 MIT 的含义或字体来源要求变化，回到研究重新收敛。
