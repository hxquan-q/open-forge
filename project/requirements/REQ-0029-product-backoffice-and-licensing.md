# 个人产品平台：账号、Web中心、市场、官网文档与下载镜像

## 用户问题

用户尚未建立自己的后台；fork保留上游云客户端但默认关闭。用户最新明确第一阶段要有个人注册登录与管理、个人Web管理端、Skill/MCP市场、官网产品介绍与文档、应用下载、依赖下载镜像；支付不考虑。此前企业授权/商务优先的阶段划分由本次范围替代。

## 用户结果

访客能了解产品、读文档并获取可信安装包；个人能注册登录、管理账号与设备、发现和收藏Skill/MCP，在Desktop确认安装/连接，依赖缺失时可靠下载。运营人员可以管理用户、目录、应用版本、镜像与故障，全程不依赖上游运营账号或服务。

## 范围

- 个人账号：注册/验证、登录/退出、恢复、资料修改、会话撤销、停用与注销流程。
- 个人Web中心：账号/安全/设备、我的Skill/MCP、收藏、按设备的安装/连接摘要与报告时间。
- Skill/MCP市场：分类/搜索、详情/来源、固定版本/兼容性、收藏、Desktop打开与安装/连接、更新/撤回及恢复。
- 官方/受邀发布者和运营后台：用户与访问权限、能力审核/发布、版本登记、镜像同步与批准、管理员角色及审计。
- 官网与公开文档：产品/功能/系统要求、快速开始、账号/市场/依赖操作与故障恢复、下载和更新日志；复用已有公开文档内容。
- 应用下载：已批准的平台/架构/版本、签名/摘要、说明和历史版，下载与更新来源一致。
- 产品依赖镜像：客户端及精选MCP实际需要的固定运行时、工具、依赖包/资源，来源/许可/完整性、重试/回退与运营状态。
- 后续路线保留企业组织/席位/策略、私有化与离线许可，不作为本期交付前提。

## 不做什么

- 本轮只调整需求与方案，不创建服务端仓库、写产品代码、注册域名、镜像/上传制品、部署或发布。
- 不考虑支付、订单/账单、回款/发票、渠道分成，不将它们作为第一期或自动后续必做工作。
- 首期不做完整企业管控、离线商业许可、全信创适配、开放任意发布者或完整开发者中心。
- 不建设通用全量npm/PyPI/GitHub镜像、任意URL代理、MCP代托管或任意代码沙箱。
- 不自动上传个人项目/会话/本地文件和MCP秘密，不把Web云记录当成对离线设备的远程控制。
- 不借用上游运营服务，也不将云登录强加为lite本地使用条件。

## Given / When / Then

- Given 匿名访客；When 访问官网/文档和下载中心；Then 能看真实支持范围并无需账号下载批准制品，链接与版本说明一致。
- Given 新个人用户；When 完成注册验证、Web登录与Desktop授权；Then 两端使用同一用户身份，恢复/退出/撤销按合同生效，长期凭据不放回调URL。
- Given 用户在市场收藏Skill或MCP；When 在应用中打开指定条目；Then Desktop重新校验目录/版本并让用户确认，不接受任意命令或免确认安装指令。
- Given 精选本地MCP缺少运行时/依赖；When 下载和安装；Then 获得正确平台/架构的固定制品并在验证后执行；网络/校验/取消失败有恢复入口。
- Given 远程MCP需要第三方身份；When 用户连接；Then 真实完成对应授权和验证，个人中心不保存或展示秘密。
- Given 某设备离线；When 用户在Web查看安装记录或解除关联；Then 展示上次报告与未知状态，不声称设备已卸载或本地数据已删除。
- Given 镜像主源故障或内容异常；When 恢复/重试/按规则切备用源；Then 保持相同版本与期望摘要，错误内容不安装，不回退到latest或其他架构。
- Given 管理员撤回某资源；When 新安装/下载或更新推荐指针；Then 新请求按状态拒绝或提示，固定版本历史和审计保留。
- Given 两个个人账号；When 一方替换另一方的设备/收藏/安装请求标识；Then 服务端拒绝跨用户读取和修改。

## 必须保持

- 身份、后台角色、功能访问、资源准入与执行批准分开；注册不会自动获得管理员或发布者权限。
- 账号/云状态与设备本地状态分开，设备记录最小化且带时间，秘密留在受保护的设备凭据存储。
- 审核通过的包和镜像制品按固定版本/摘要不可变，来源/许可证和发布证据可追溯；哈希不自动等于来源背书或沙箱隔离。
- 既有市场类型/源身份、主进程接线、lite模式、更新协议、工具选择和生命周期语义有明确兼容路径。
- 公共文档单一事实源、既有双语/URL规则与公开边界保持；不公开内部ADR和私有配置。
- 只对实际验证的平台/架构及Skill/MCP组合承诺可用；预备的部署/网站不等于已经发布。
- 上传、部署、生产发布和实际域名/外部资源开通仍另行授权。

## 验收标准

- 第一阶段联合通过从官网了解/下载、注册恢复、Web个人管理、Desktop登录、市场发现到安装/连接和依赖下载的连续用户流程。
- 两种市场有真实可用样本、失败恢复、撤回与兼容证据，不能只交付空目录或只验证Mock调用。
- 镜像覆盖首批实际依赖，含中断恢复、缓存验证、错误摘要/架构、取消/重试和备用源；不能只修改下载URL。
- 基础运营后台能实际维护用户、审核目录、批准版本和镜像，管理员分权与审计有效。
- 官网/文档/市场/下载与客户端引用相同批准资源，公共链接、双语、搜索及未支持平台反馈符合合同。
- 跨用户访问、会话撤销、账号停用/注销与个人秘密隔离有服务端证据。
- 企业席位/策略、商务及支付不作为这次第一期验收门槛。

## 风险与失效条件

首批域名/部署地区、邮箱与身份组件、发布平台架构、官方Skill/MCP清单、镜像流量/容量、可再分发资产范围和云端观察记录保留规则需要实施时明确。若要求个人开放发布、完整包仓镜像、云执行或远程设备管理，需另定安全/规模/数据边界。

方案与证据见 [PLAN-0023](../plans/PLAN-0023-product-platform-backoffice.md) 和 [RESEARCH-0041](../research/RESEARCH-0041-product-backoffice-and-enterprise-control.md)。
