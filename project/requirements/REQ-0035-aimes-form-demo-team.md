# AIMES 表单演示团队

## 用户问题与结果

正式 eform 团队面向完整二开，流程对原型演示过重。新增独立的 Code Team，以主控、需求、原型、测试、部署五个角色快速交付能从 AIMES 菜单打开的表单演示，不改变正式团队。

## 范围与边界

- 五角色均以轻量原型演示为任务前提。项目文件只用于核实必要的接入、构建和兼容事实，不引入正式开发流程。原型成员开发后只做静态自审，不编写或执行测试用例；不在业务界面上提示原型或非生产身份。

- 主控只沟通、协调、协助，不增加产物校验或额外审批。需求确认列表、表单、字段语义和核心流程；已知对象和对象/文本不明时用对象，只有确认为文本的字段才用文本，明确的其他标量保持自身类型。
- 原型用 Vue + Vite + 随包 JSON mock，只让本次演示表单不新增或依赖真实后端；不改变既有模块的后端、路由和真实接口。演示静态资源相对寻址，独立预览不需 Node 或本机外部数据。样式尽量贴近 AIMES，不影响速度和核心流程。
- 测试成员只做必要的构建检查与静态代码/制品审视；单元测试按需求自行决定，能不做就不做。演示团队不执行实际交互或操作测试。本机预览和 AIMES 菜单内的运行态验收步骤记录在文档中，留给用户。
- 在获准的目标仓库先提交并推送私有分支，再取最新 `master` 合入本地私有分支。其他不可调和冲突以 `master` 为主，保留演示 mock、无新增后端和相对资源路径，不影响既有模块。用同一合并候选打包完整 CustomDev 前后端及必要依赖，交付部署文档；未获准的远端和测试环境操作不执行，不做生产部署。

## Given / When / Then

- Given 一个含物料选择的表单需求，When 用户选演示 Team 发起任务，Then 得到能从列表进表单并完成核心操作的演示，物料保持对象，名称保持字符串。
- Given 同一合并候选，When 本机预览或从测试环境 AIMES 菜单进入，Then 演示使用相同 mock 初始数据和核心业务逻辑，测试环境中的既有模块仍能调用真实后端。独立预览不是完整部署制品，也不替代真实接入。

## 验收与风险

两支团队可同时选择，演示 Team 具备五角色、完整装配及发布配置。携带测试环境入口、路由和验收步骤交付，缺权限或主壳事实时明示待验证；合同测试不等于模型遵循或实际部署通过。
