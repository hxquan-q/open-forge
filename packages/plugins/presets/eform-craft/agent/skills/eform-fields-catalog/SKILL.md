# 电子表单工坊·常见表单字段（eform-fields-catalog）

本手册是**常见字段类型的查表参考**：开发表单时，遇到某个格位"在系统里该是什么字段"，查这里确认它的**类型（fieldType）、值结构、存什么、画成什么控件、怎么从原件识别**。

eform-craft §1 只负责"从原件识别类型的标记（识别合同）"与"固定命名映射"；字段类型的完整语义——值结构 / 存储形状 / 渲染控件 / 识别要点——以本手册为权威参考，不再在 §1 重述。

> 用法：进行任何表单开发前，请先通过本手册预确定各字段的类型。**通常情况下常见字段类型都已覆盖；若遇见本手册未包含的字段类型，必须向用户确认，不要自行臆造。** 标记缺失、或遇到分录/主数据引用/复杂类型时，也查本手册。字段**落在哪一层**（单据头/单据体/子单据体）见 `eform-structure-templates` 结构模板 skill。

## 0. 速查总表

| 业务叫法 | fieldType | 值结构 |
|----------|-----------|--------|
| 文本 | string | 单string |
| 长文本 | string | 单string(多行) |
| 整数 | int | 单int(整数) |
| 小数 | double | 单double(小数) |
| 日期 | date | 单string(yyyy-mm-dd) |
| 长时间 | datetime | 单string(yyyy-mm-dd HH:mm:ss) |
| 短时间 | time | 单string(HH:mm) |
| 布尔 | boolean | 单boolean |
| 基础资料 | object | 多属性对象(就像编程里的class对象) |
| 下拉列表 | select | 单string(选项code) |
| 单据体 | entry | Array<Row> |
| 子单据体 | subEntry | Array<Row>(嵌行内,可自嵌套) |

## 1. 标量字段（单值）

每类统一四要素：**是什么 / 存什么 / 画什么 / 怎么识别**。

### 1.1 文本（string）
- 是什么：自由文本。
- 存什么：`values[F#]: string`（容量 ≥ 256）。
- 画什么：单行 `<input type="text">`；控件带 `data-fid="F#"`；紧邻灰字「类型:文本」标注。
- 怎么识别：§1 `[文本]`，或"有文本、无标记的活动区"。内容明显要换行/大段 → 升级为长文本（string·多行）。

### 1.2 长文本（string·多行）
- 是什么：多行大段文本（备注、说明、原因），是 `string` 的多行变体。
- 存什么：`string`。
- 画什么：`<textarea>`。
- 怎么识别：原件该格是明显的多行填写区 / 备注栏；或文本容量不够时升级。建议标记 `[长文本]`。

### 1.3 整数（int）
- 是什么：整数值（数量、序号）。
- 存什么：`number`（整数）。
- 画什么：`<input type="number" step="1">`，录入拒绝小数。
- 怎么识别：§1 `[整数]`。默认非负；需负数时原件明示负号或旁注"可负"。

### 1.4 小数（double）
- 是什么：带固定小数位的数值（金额、比率、重量）。
- 存什么：`number`；显示按标记小数位定宽（`[小数,2]` → 2 位）。
- 画什么：`<input type="number" step="0.01">`；金额类建议右对齐 + 千分位。
- 怎么识别：§1 `[小数,2]`（位数列推 `[小数,3]`…）；与 `entry` 配合时行内小计/合计走 `formula` 联动（eform-craft §3.3.7）。

### 1.5 日期 / 长时间 / 短时间
- **日期** `date`：§1 `[日期]`；`yyyy-mm-dd`；`<input type="date">`。仅日期，不含时刻。
- **长时间** `datetime`：§1 `[长日期]`；`yyyy-mm-dd HH:mm:ss`；`<input type="datetime-local">`。含**日期 + 时刻**（如"2026-10-10 14:30:00"）。
- **短时间** `time`：建议标记 `[时点]`；`HH:mm`；`<input type="time">`。**仅时刻**（如"14:30"，用于班次、时点字段）。
- 怎么区分：无特别说明则默认"日期=date"（仅日期）、"时间=datetime"（日期+时刻）；纯时点(`HH:mm`)需显式 `[时点]` 标记，不默认归入 datetime。

### 1.6 布尔（boolean）
- 是什么：是非二值。
- 存什么：`values[F#]: boolean`。
- 画什么：两个单选（是/否），默认未选或按原件默认勾选。
- 怎么识别：§1 `▇是 □否`。

## 2. 引用字段

### 2.1 基础资料（object）
- 是什么：指向一条**主数据记录**（组织/部门/物料/客户/人员/仓库…），金蝶里统称"基础资料"，以"编码 + 名称"唯一标识；不是自由枚举。
- 存什么：`values[F#]: { code: string, name: string }`；显示取 `name`，提交/存储带 `code`。
- 画什么：lookup 选择器——输入框 + 下拉候选（展示 name，回填空 `{code,name}`）；一期无主数据服务时以 `select` 模式 mock（示例组织A/B、张三/李四，遵守 eform-craft §0 mock 纪律）。
- 怎么识别：原件该格语义是"从某名录选一个"且候选来自主数据（如"往来单位""收货仓库""物料编码"）；或命中 §1 的 `[组织]`/`[部门]`/`[品名]`/`[工序]`/`[人员]`——这些一律归 `object`（基础资料大类），由主数据 lookup 取。
- **与 select 的关系（重要）**：候选**固定且少量** → `select`（下拉列表）；候选**来自主数据、可能很大** → `object`（基础资料，lookup）。两者都可能表现为"从名录选一个"，看候选规模与来源决定；`[组织]` 等标记一律归 `object`。

### 2.2 下拉列表（select）
- 是什么：固定短枚举（来源已知、数量有限），如性别/状态。
- 存什么：`values[F#]: string`（取选项 code 或展示值）。
- 画什么：`<select>` + 选项组；选项来自 schema `field.options[]`（mock 用示例占位）。
- 与 object 的取舍：候选**固定且少量** → `select`；候选**来自主数据、可能很大** → `object`(lookup)。两者都可能表现为"从名录选一个"，看候选规模与来源。

## 3. 复合字段（分录）

### 3.1 单据体（entry）
- 是什么：一张单里的**明细行集合**（入库单的物料明细，每行 = 一个物料 + 数量 + 单价 + 金额）。也叫"分录""明细体"。
- 怎么识别（**结构性，无文本标记**）：原件出现**重复行模式的网格**——同一组列标题下多行可填、且行数不固定 → 判定为单据体；其列标题即分录字段。
- 存什么：`values[F#]: Array<Row>`。
- 画什么（form.html）：单据体区渲染为一个**可编辑子表格**——列 = `entryFields`，行 = 数据；每行「删除」键（draft/saved 可用），表尾「+ 新增行」；行内 `formula` 字段实时联动（改数量/单价重算金额）；表尾可加「合计」行（对小数列求和）。`data-fid` 写到单据体容器与每行控件（如 `data-fid="F7.2"` + `data-ridx`）以便审计快照与校验。
- schema 形态（嵌套于 `fields[]`）：

  ```jsonc
  {
    "id": "F7", "label": "物料明细", "fieldType": "entry",
    "entryCaption": "明细行",
    "entryFields": [
      { "id": "F7.1", "label": "物料", "fieldType": "object", "required": true },
      { "id": "F7.2", "label": "数量", "fieldType": "double", "required": true },
      { "id": "F7.3", "label": "单价", "fieldType": "double" },
      { "id": "F7.4", "label": "金额", "fieldType": "double", "formula": "F7.2 * F7.3" }
    ],
    "allowAdd": true, "allowDelete": true
  }
  ```

- 生命周期：单据体随所属记录走 draft→saved→approved；approved 后整表只读（增删改禁用）。
- 列表页（index.html）：单据体不单独成记录，仅在「查看」中展开。

### 3.2 子单据体（subEntry）
- 是什么：嵌在单据体**某一行内**的第二层分录（工单：工序分录 → 每道工序下的"耗用物料"子分录）。也叫"子分录""嵌套明细"。
- 怎么识别：单据体某列内又出现**可展开的子行网格**（行内再分行）→ 该列对应子单据体。
- **允许自嵌套**：子单据体行内还可再带子单据体（如子分录下再分子分录），层级不封顶，深度由业务决定——呼应结构模板 skill 的"层级逻辑"口径，这里只管字段类型，不限制嵌套层数。
- 存什么：`values[F#][i][subF#]: Array<Row>`（嵌于 entry 行内）。
- 画什么（form.html）：单据体行内，对应列渲染为「展开子表」→ 弹出/内嵌二级可编辑子表格（列 = `subEntryFields`）。两级均可增删行、formula 联动；approved 整体只读。
- schema 形态：在 `entryFields` 的某字段上挂 `subEntryFields`：

  ```jsonc
  {
    "id": "F7", "fieldType": "entry", "entryCaption": "工序",
    "entryFields": [
      { "id": "F7.1", "label": "工序", "fieldType": "object" },
      { "id": "F7.2", "label": "耗用物料", "fieldType": "subEntry",
        "subEntryFields": [
          { "id": "F7.2.1", "label": "物料", "fieldType": "object" },
          { "id": "F7.2.2", "label": "用量", "fieldType": "double" }
        ] }
    ]
  }
  ```

- 约束：子单据体应位于 `entry` 行内，不作顶层字段。

## 4. 其他字段（非数据 / 跨 agent）
- 电子签（signature）：字段类型与注入由 **esign-craft 技能（电子签名专员子agent）** 定义，不在本主 agent 字段目录范围内；本手册不覆盖其语义，识别到 `[电子签]` 时按 eform-craft §4 流程派工给 @esign。
- 固定标题（static-label）：无值布局元素，仅作版面分区 / 说明文字（§1 中"有文本、无标记的活动区"）；由主 agent 负责渲染，不参与数据存储。

## 5. 识别决策流程（给 eform 用）
1. 原件格位有 §1 标记 → 直接定型（含 `[长日期]`/`[小数,n]`/`[组织]`…）。
2. 无标记但语义是"从名录选一个" → 看候选：固定少量 → `select`；主数据 → `object`（或命中 §1 的 `[组织]`/`[部门]`/`[品名]`/`[工序]`/`[人员]` 一律归 `object`）。
3. 区域呈**重复行网格** → 单据体（entry）；其行内再嵌套子网格 → 子单据体（可多层）。
4. 拿不准（单据体 vs 普通多值、object vs select）→ 标 `【推断】`，确认门请用户指认（eform-craft §5）。
5. 复合字段（单据体/子单据体）的编号、公式、合计要在 schema 显式建模，页面与 schema 永不分叉（沿用 eform-craft §0 F# 三体一致与 §7 修改循环）。

## 6. 边界
- 本手册是字段类型的**唯一权威**；eform-craft §1 仅保留识别标记与固定命名，不再定义字段语义，避免两处漂移。
- 本手册只定义字段语义与存储/渲染范式；不定义页面视觉 token（见 eform-craft §0 页面标准）与派工（§4）。
- 终期映射：fieldType 枚举即 Vue 控件选型单；`object`/`entry` 的取数与存储终期整体替换为 MES 服务与后端，结构层不动（eform-craft §9）。
