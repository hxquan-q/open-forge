# 表单操作审计

“新增/修改”指审计功能本身，不是只审计新增/修改两类业务动作。需求阶段先确定单条记录内容，纳入需求闭环，开发再按已确认目标实现；具体动作不从旧 Demo 事件清单自动扩展。

## 单条记录

1. 操作者：从目标项目可信身份上下文取得，不相信客户端自报身份；归属元数据规则见 [用户元数据](../user-metadata-and-audit-boundary/SKILL.md)。
2. 操作时间：服务端可核实的时间。
3. 表单/记录标识：是哪类表单的哪条记录。
4. 稳定业务动作/按钮标识：显示文案只能附加，不能是唯一标识。
5. 操作结果：成功/失败，失败尝试是否记录及原因粒度按需求确认。
6. 操作后的必要字段：只记录用户要求体现结果的部分数据，不默认保存完整表单快照；排除/脱敏敏感和无关字段。

日志反映服务端实际动作/结果而非浏览器点击；成功事件的时间与数据须对应实际完成状态，不能在提交失败前记成成功。

## 接入和验证

沿用目标表单/项目已核实的既有记录方式，平台日志先例见 [项目事实](../project-architecture-and-runtime-map/SKILL.md#单据与日志参考)。先核对事件覆盖、事务/失败一致性、操作者来源、敏感字段及访问授权，再实现本记录需求。没有可用既有方式时报告缺口，向用户确认局部方案，不自动扩为平台。

按实际范围验证事件与结果一致、必要操作后数据、失败行为、访问与脱敏；不以客户端无删除按钮声称服务端不可篡改。保留/导出/防篡改若涉及本次需求，先明确项目合同；不自建动态审计配置中心、统一查询/导出平台、全局保留/归档或防篡改平台。

仅 creator/modifier 元数据、电子签或纸面签字栏不触发；这些不等于操作历史。旧 `eaudit-craft` 的固定五类事件、localStorage、JSONL 下载和查看器是历史演示，不是当前实现协议。

来源：已审阅同名候选、旧 eaudit 领域材料与现有用户元数据 Skill；领域范围以当前用户需求为准，不把候选视为批准的外部审计接口。
