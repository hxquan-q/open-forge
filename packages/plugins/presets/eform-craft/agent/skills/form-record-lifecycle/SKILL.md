# 单据生命周期（条件型）

面向一条已填写的业务记录，不是表单版式或 Agent Team 工作流。只有需求或已核实项目行为显示状态流转时才调用；普通保存/关闭并不自动需要额外状态机。若仅有保存/取消，记录实际行为并辨清取消是关界面还是业务撤销，不强行引入提交/审批。

## 建模

先读当前目标单据的源码、持久化状态、允许操作与实际触发主体，确认：

1. 状态及业务含义，谁通过什么动作触发；
2. 迁移的前置条件、失败结果、可逆性与撤回/反审核要求；
3. 每状态的编辑、删除、重存、签名和其他动作限制；
4. 服务端授权与状态校验位置，不能只禁前端按钮；
5. 与数据保存、事务、并发、重复请求和历史记录的关系。

用状态/迁移/约束表和可验证场景表达，未知状态名/权限/锁定先待验证；附件签字或按钮文案不是充分证据。平台已核实存在审核模型和工作流引擎先例，见 [项目事实](../project-architecture-and-runtime-map/SKILL.md#单据与日志参考)，应评估复用，但具体单据的状态集合仍按需求确认。

## 验证与边界

覆盖允许/拒绝迁移、编辑/删除限制、重复/并发和失败后的实际状态，不把局部客户端状态当服务端约束。是否涉及电子签/操作审计保持各自触发条件，见 [电子签](../electronic-signature-field-implementation/SKILL.md) 和 [操作审计](../operation-audit-domain/SKILL.md)，不因状态建模自动增加能力。

旧 preset 的 `draft→saved→approved`、终态全锁定和浏览器持久化只是演示合同，不是 CustomDev 默认；历史本地扫描没找到业务页面也不能证明目标环境没有审批。

来源：已审阅同名候选、旧 preset 生命周期抽象及 2026-11-06 项目证据。低优先级表示条件适用且不作为所有需求的前置门槛。
