# 实体表单附件解析

面向 AIMES CustomDev 的附件需求入口；本 Skill 只处理可见结构，不是平行的需求/开发流程。解析完成后必须把结构化结果与用户需求一并交给 [需求到实现闭环](../requirements-design-to-delivery/SKILL.md)，不能因解析结束而跳过需求澄清和规格确认。

## 触发与边界

用户提供图片、PDF、Excel、Word 等电子化实体表单附件作为需求/二开来源时使用。没有表单附件的一般二开、仅自然语言设计/API/数据库/部署需求、与表单无关的附件均不触发。纸面签字栏只记录可见区域，不能单凭它推导电子签、身份认证或审批要求。

## 解析方法

1. 先看整体页次、标题、分区和网格，再逐格记录原始标签、位置、行列/合并关系、提示文字、选项及原件标记；固定标题/说明与可录入区域分开。
2. 同一列标题下的可变重复行记录为疑似单据体；行内再次出现重复子网格记录为疑似嵌套明细。保留头/体/子体分层思维，允许多明细、仅头和多层嵌套，但不强制原件套成固定三层或某份 JSON 骨架。布局证据不足以确认业务层级时标为推断。
3. 保留原文，不把标签改成数据库列、Java 属性、DTO/API 参数或旧固定业务别名；类型标记只作输入证据，不在解析阶段解释成规格类型、取值或权限。
4. 可见事实、推断、裁切/模糊/无法识别项分别标注；不猜成确定内容，指出页/区域并请求补件或用户澄清。

## 格式与工具限制

工具以当前会话实际清单为准：图片用可用视觉/OCR 核对；PDF 优先文本层并结合页面图像确认布局，扫描件需视觉；Word 有转换/解析能力才用，否则请用户导出 PDF/截图；Excel 读取单元格、合并与重复结构，数据画像不能代替视觉布局；旧格式不可读时请另存受支持格式。CSV/TSV 可直读，但不能还原其没有的版式。缺能力时明确说明，不伪造识别结果。

## 输出

来源、页次/区域、原始字段标签/标记、位置/层级/重复关系、证据与待确认项。可选 F# 仅作非展示关联标识，不能显示为 Fxx 字段名前缀，也不是数据库主键或 API/DTO 属性。

字段规格交给 [字段规格与基础资料](../form-field-specification-and-base-data/SKILL.md)；不决定默认/公式、状态机、电子签身份、审计、DDL 或实现组件，不生成原型/工程代码。
