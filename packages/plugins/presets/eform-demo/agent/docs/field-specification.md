# 字段规格与基础资料（演示）

接收附件中的原始字段或自然语言需求，输出演示唯一的一份字段规格，供原型和测试共用。不重新解析附件，不查库，不推断生产 API、DTO、数据库列或权限。

字段类型按两步判定，顺序固定：先过**实体判定门**，再给未过关字段分配**标准类型**。不跳步，不把两步混成一次判断。

## 第一步：实体判定门（每个字段只答一个问题）

问题：该字段的值域是不是基础资料实体的引用？（物料/品名、工序、人员、组织、供应商、设备、客户等。）

- 是，或**不确定** → 建模为 `object`，不确定时标注「演示假设」。`string` 在这一步不是选项。
- 单属性引用同样是对象：表单只有「品名」一列，它也是物料对象的引用，不因「表单里没出现物料编码」而降为文本。
- 同一实体的多个属性同现（如工序编码 + 工序名称）→ 合并为同一对象的多个字段，不拆成两个无关类型。
- 原件介质形态（纸质、Excel、手填、预印勾选框）只说明录入方式，永远不是类型证据；「原件是手写填空」推不出「字段是文本」。
- 只有值域本身不是实体引用的自由字段（备注、说明、检查意见）和纯编码（批号、单据编号）才进入第二步。

## 第二步：标准类型分配（仅对未过关字段）

| 规格类型 | 语义与确认项 |
|---|---|
| `string` | 自由文本或纯编码，如姓名、备注、批号、编号。数字外观的编码仍是文本，保留前导零。 |
| `number` | 明确的数量、金额、比例或普通整数；区分整数和小数，按核心操作确认单位、允许范围和舍入。 |
| `boolean` | 是/否，缺省和未填写不自动等于否。 |
| `date` / `datetime` / `time` | 日期、日期时间、时刻分别定义；JSON 可用约定格式的字符串表示，但业务规格不降为普通文本。涉及跨机器日期展示时固定有意义的时区与格式。 |
| 固定枚举（单选） | 值域是固定清单，如合格/不合格；写明值类型、值与标签，不伪装成远程基础资料。 |
| 多选 | 已确认的固定集合多选；说明元素、有无顺序及对应的核心业务规则。 |

## 对象与集合建模

- `object` 是基础资料引用，有当前项目中已核实的参考形状就优先参考；没有时按演示需要定义最小 mock 形状，例如 `{ id, code, name }`；这是 mock 形状，不承诺正式接口也用这些键。区分选择对象与展示值：`material` 是物料对象，`material.name` 才是文本。列表可显示名称，表单选择、mock 保存和回显不能把实体压成名称或 ID 字符串。
- `array<T>` 用于明细行（`array<object>`）等已确认集合；说明元素字段与对应的核心业务规则。
- 未选中、空对象、空字符串不要混用。普通签字栏按原语义记录，不自动生成电子签。

## 原件证据与交接

原件介质只证明录入方式，不证明字段类型。是/否、整数/小数、日期/时点按语义在第二步转为上表类型；不把原件标签当数据库列名；关联标记不作为页面前缀。

短规格写清标签、字段键、唯一类型、对象/明细形状与虚构样例。只为影响核心流程的字段补齐取值来源、默认值/枚举、公式、单位与精度、空值、联动及可见结果。保留已确认、演示假设和待核实的区别。例：品名过实体门判定为物料对象，选定 `material` 后带出显示单位，数量 `2` 保持数值，保存后列表显示 `material.name`，重新进入表单仍选中原对象。
