# 完整打包、AIMES 接入与回滚

本指南只处理 CustomDev 制品和 AIMES 测试环境。Git 顺序、授权与冲突优先级按部署角色 Prompt。本次演示表单用 mock、无需新增后端；完整部署仍包含既有前后端，不得以本机可预览为由省略后端。

## 构建证据

- 合并无冲突就按项目实际脚本和锁文件直接打完整前后端；只在实际冲突解决后、打包前按受影响范围做必要验证。前端交完整 `dist`，保留既有模块、真实 API 接入和本次演示资源；后端交项目已有的服务制品及运行所需的依赖和资源。不猜目录或打包命令，不裁剪既有模块或部署配置。
- 两端构建成功后，直接把候选提交、构建结果和已知的制品路径写入部署指导，不加跑测试或制品复验。任一端的构建失败都不能称为完整交付。
- 本机只预览本次演示，不要求运行其他业务模块或后端。用同一候选中的演示静态资源和内置 mock 预览，文件协议受限则用本地静态 HTTP。如果完整前端必须经主壳启动，提供同一候选构建的独立演示入口，并明确它不替代完整部署制品。

## qiankun 接入参数

用构建前已核实的源码、配置及成员交接填写以下参数，不把写部署指导变成构建后的检查阶段。

- 菜单路由只负责宿主导航；指导应区分目标测试主壳的 qiankun 子应用名、`entry`、`activeRule` 与业务路由。`entry` 是子应用 HTML 入口，不是宿主业务路由。说明复用现有注册还是新增演示注册，不从参考环境抄地址、目录或注册名。
- 写清菜单进入演示列表的路径，以及静态目录、子应用入口和 `base: './'` 的关系；无法从已核实信息确定的值标为待确认，不覆盖其他模块。

## 给用户的部署、验收与回滚步骤

1. 指导用户核实目标测试环境、前后端目录和服务归属，备份上一版匹配的前后端制品及菜单/注册配置，再按项目已核实的步骤更新完整制品；仅当目标流程需要时更新或重启目标服务，不触碰其他服务或生产。
2. 主壳是否实际挂载、真实 API 是否可用只能通过运行态验收确认。把从 AIMES 菜单进入并完成核心操作、确认一条既有模块的真实接口仍可用的步骤写进指导，由用户自行决定是否执行。团队不打开页面、不请求真实 API，也不报告未执行的验收通过。
3. 给用户写明失败时如何恢复上一版匹配的前后端制品及菜单/注册配置。如果仅撤回本次新增演示入口，只移除其专属资源和配置，不覆盖其他模块。

交付文档记录构建证据、部署步骤、实际入口和路由、测试步骤及回滚点。参数未获核实就列明缺项、证据来源和由谁补齐；只给可验证的命令，不写秘密，不把本地预览或静态地址可达记成 AIMES 接入通过。
