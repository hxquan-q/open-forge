# 部署信息卡（AIMES 测试环境）

Git 顺序、授权与冲突优先级按部署角色 Prompt：提交并推送私有分支、拉取最新 `master` 合入、用项目实际脚本打前端包，然后按本卡完成部署与注册。

## 固定规则（模板写死，成员不改）

- 部署方式固定为**备份后替换**；备份可省略——未备份时，拿 `master` 单独重新打一版即可恢复。
- 后端无改动：不打 jar、不替换 jar、不重启服务。
- 标（固定）的值不可改写；其余每项必须有值，或标「待确认（缺什么）」；不猜目录、地址或凭据，不填任何密钥。
- 本卡即最终交付的部署文档，不再另写叙述性说明。
- 本卡交用户执行；团队只产出本卡，不登录测试服务器或 AIMES、不代做替换与注册。

## 流程引导

**① 替换测试服务器前端包**

1. 登录「测试服务器IP」。
2. 先备份「测试服务器前端资源路径」下的现有内容（可省略）。
3. 将本次构建的前端包替换掉该路径的已有前端资源包。
4. 退出登录，进入下一部署流程。

**② 注册菜单项**

1. 登录「测试环境地址」的 AIMES 系统，点击左侧「平台设置」页签，在展开的功能面板中点击「系统配置」→「菜单管理」。
2. 在「拆改配业务/新增表单」目录下新增一个菜单项。
3. 菜单项的各项属性填写如下表，并点击保存。
4. 回到首页，刷新缓存，点击刚刚新增的菜单项，正常进入表单模块则算成功。
5. （如果遇到刷新之后点击菜单仍为空白模块页，则有可能是缓存过重，请禁用缓存或者确保缓存的清理时间为不限制）
