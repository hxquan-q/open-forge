# 部署信息卡（AIMES 测试环境）

Git 顺序、授权与冲突优先级按部署角色 Prompt：提交并推送私有分支、拉取最新 `master` 合入、用项目实际脚本打前端包，然后按本卡完成部署与注册。

## 成员守则（模板写死，不进卡面）

- 流程：拉取最新 `master` 合入私有分支 → 用项目实际脚本打前端包 → 替换测试服务器前端包 → 核对/注册菜单项。
- 部署方式固定为**备份后替换**；备份可省略——未备份时按卡内「回滚」节恢复。
- 后端无改动：不打 jar、不替换 jar、不重启服务，不做数据库变更。此约束只约束你自己的动作，不写进卡面。
- 交付物只有本卡：对下方模板**只做填值替换**（`<...>` 占位换成实际值；标（固定）的文案原样保留），不得增删章节、调整结构或改写模板文案；模板没写的一律不写。
- 卡面按正式交付口径书写：只写部署、核对与恢复所需信息，不写实现方式、数据性质或构建细节。
- 标（固定）的值不可改写；其余每项必须有值，或标「待确认（缺什么）」；不猜目录、地址或凭据，不填任何密钥。
- 本卡交用户执行；团队只产出本卡，不登录测试服务器或 AIMES、不代做替换与注册，也不声称已部署或验收通过。

## 二、流程①：替换测试服务器前端包

1. 登录「测试服务器IP」。
2. 先备份「测试服务器前端资源路径」下的现有内容（可省略）。
3. 将本次构建的前端包替换掉该路径的已有前端资源包。
4. 退出登录，进入下一部署流程。

## 三、流程②：注册菜单项

1. 登录「测试环境地址」的 AIMES 系统，点击左侧「平台设置」页签，在展开的功能面板中点击「系统配置」→「菜单管理」。
2. 先核对「拆改配业务/新增表单」目录下是否已有同名菜单且路由地址与下表一致：已有则只核对，不新增。
3. 若不存在，在「拆改配业务/新增表单」目录下按下表新增一个菜单项，并点击保存。

| 字段 | 值 |
|---|---|
| 上级菜单 | 拆改配业务/新增表单（固定） |
| 菜单名称 | <本次演示菜单名> |
| 菜单类型 | 功能（固定） |
| 路由地址 | /home/custom-dev/<本次演示路由段> |
| 动作类型 | Qiankun微应用跳转（固定） |

4. 保存后回到首页，刷新缓存，点击该菜单项，正常进入表单模块则算成功。
5. （如果遇到刷新之后点击菜单仍为空白模块页，则有可能是缓存过重，请禁用缓存或者确保缓存的清理时间为不限制）
