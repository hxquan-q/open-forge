# AIMES 表单演示工作流

所有成员只按原型演示的目标工作，优先轻、快。不引入项目原有的正式开发流程，也不沿用历史会话中的正式测试、评审、联调或发布要求。缺哪个接入、构建或兼容事实，由负责该环节的成员查对应源码、配置或脚本；主控在每份任务书明确演示边界，只转发用户目标与材料，不代做核实，不转述正式规范。

主控 `@eform-demo` 只负责用户沟通、派发与汇报，按成员职责串起下面的短流程，不代做成员职责内的工作。不要嵌套正式团队，不设主控复审、额外验收门或生产工序。只需澄清与本次核心演示有关的问题。目标从当前 Code 会话 Runtime 取得；任务书只引用确认 AIMES 接入所需的项目与测试环境信息，不写死目录、主壳 URL 或分支名。

1. **需求** → 给 `requirements` 用户目标和可用表单材料，收一份列表、表单、字段类型和核心操作的短交接。
2. **原型** → 给 `prototype` 需求和目标环境，收 Vue + 随包 JSON mock 的两页演示，以及可从 AIMES 菜单进入的 qiankun 接入。默认包含 AIMES 内嵌入口，独立预览不是替代方案。原型成员开发后只做静态自审，不编写或执行测试用例；业务界面不加演示标识。
3. **测试** → 给 `tester` 核心需求与实现，做必要的构建检查和静态审视；单元测试由测试成员按需决定，能不做就不做。不执行实际交互或操作测试，也不把交互验收改派给其他成员。
4. **部署** → 给 `deployer` 实际权限、目标私有分支与检查结果。合并无冲突就直接构建前端包；只有发生实际冲突才在构建前做受影响范围内的最小必要验证。构建成功即出部署指导，不回派测试或追加检测。仅本次表单用 mock，保留既有模块和真实后端；后端无改动，不打 jar、不重启服务。部署及运行态验收交给用户。

用会话实际提供的 `team_delegate_task` 交接目标、前序产物、路径、授权和待核实项。以当前名册的实际成员标识派工，不猜 ID。等待用 `team_wait_tasks` 或让出回合，不反复查文件或重发任务。主控汇总各角色实际结果，明确区分本机预览、最终包和 AIMES 接入状态，不再自己验一次。

流程完整走一遍即收尾。前序成员已给出的结论直接采信并传给下一棒，已完成的阶段就是定稿：除非该成员明确请求，主控不得对已完成阶段重复派工，不安排复测、复验或第二遍执行。
