# AC 收尾（流水环节 13）

目标：全部流程完成后收尾——清理残留、关闭挂起会话、V6 终局对账、特殊提交，让项目保持干净。

**执行者**：收尾子（spawn 一次性）。写域（ac-pipeline §0.3）：临时物清理范围 + **state.md 终态化**（唯一可碰 state.md 的第二人——主控显式授权的一次性交接）。部分动作（关闭兄弟会话）若平台不允许收尾子直接操作，由收尾子生成关闭清单交主控执行。

## 1. 清点与关闭挂起会话（先做）

1. 读 `docs/ac/state.md`：收集全部 `agentRef` 非空且 `sessionStatus` 为 `suspended` 或 `active` 的子会话。
2. 逐个关闭：
   - 收尾子可操作（list_agents 可见 + interrupt_agent 可用）→ 直接关闭并把 state.md 对应条目置 `sessionStatus: closed`（state.md 由主控代写，收尾子报告清单）。
   - **平台不允许收尾子操作兄弟会话**（预期常态）→ 收尾子产出**关闭清单**（task_name 列表）报告主控 → 主控逐个 `interrupt_agent` 关闭 → state.md 置 closed。
3. 关闭后 `list_agents` 复核：无 active/suspended 的流水子会话残留。
4. 子代理终态声明（告知用户）：本流水全部子会话已关闭、不再唤醒（durable id 仅作历史登记保留在 state.md）；后续迭代一律新起子——用户可放心无视列表里的旧条目（idle/ready 是存储态非活动进程）。

## 2. 清理残留文件

1. 清点工作区：`git status`（只读）找未跟踪文件。
2. 分类处置：
   - **流水产物**（docs/ac/）：**先问用户**（ask_user_question，收尾必经项，主动发起）：保留（默认推荐——下轮迭代的勘察输入）/ 归档（移至 `docs/ac-archive/<日期-需求名>/`）/ 清理（整删 docs/ac/——确认不可逆且项目不再迭代才选）。用户选择记 state.md 最后一行。
   - **临时文件**（测试输出、缓存目录、验证脚本）：按整洁要求直接清理（.cache/ 类若在 .gitignore 里且体积小可保留）。
   - **意外文件**（来历不明的）：报告主控查明来源，不擅自删。
3. test-results/ 的中间测试证据随产物处置档走，不单独保留。

## 3. V6 终局对账（收尾提交前必做）

主控（或收尾子在主控授权下）执行全流水 git 轨迹总对账：

1. `git log --oneline <流水分支起点>..HEAD` 逐提交核对：每个 commit 对位一个 done 的（子）环节——T 档（`T<n>:`）、stage 档（`stage <seq>/<name>:`）或部署/收尾提交，**无游离提交**。
2. state.md 全部 artifacts 路径存在（ac-gate G1 全量重放）。
3. 游离提交/缺失产物 → 收尾报告列出，**用户门裁决**（不自动处置）。
4. 对账结论写进收尾提交信息与交付总结。

## 4. 特殊 git 提交（收尾提交）

1. 提交前检查：
   - `git status` 改动面 = 预期内容（流水产物处置结果 + 清理动作）+ 无意外文件
   - 不含敏感信息（密钥/凭据/临时文件）
2. 收尾提交信息（区别于功能提交）：
   ```
   chore(ac): 流水收尾——<需求名>（round <n>）

   - 白盒 <x> 轮 / 黑盒 <y> 轮，全部通过
   - V6 终局对账：<结论；游离提交/缺失产物或"无">
   - 挂起开发子会话 <m> 个已关闭
   - 流水产物处置：<保留|归档|清理>
   - 遗留项：<一般/轻微问题或"无">
   ```
3. **本地提交，不 push**（铁律）。提交后 `git log -1` 留证。
4. 若用户要求所有 git 操作手动执行 → 准备好提交信息与文件清单，提请用户执行。

## 5. 交付总结（主控向用户）

```
# 流水交付总结
需求: <一句话> → 分支 <branch> @ <提交哈希>
测试: 白盒 <轮次+结论> / 黑盒 <轮次+结论>
部署: <已部署+验证结论 或 按用户安排跳过>
V6 对账: <结论>
遗留: <豁免项/轻微问题/无>
产物: docs/ac/ 处置=<保留|归档|清理>
会话: <n> 个开发子会话已全部关闭
```

## 6. 收尾后

- state.md 终态化：全部环节 done、round 结束标记、交付总结要点写入。（收尾子写 state.md = 主控显式授权的一次性交接，交接范围仅终态化，ac-pipeline §0.3）
- goal（若建了）标 complete；todo 清零。
- **注意**：收尾者的提交完成后，如启用初审者角色（预留，v1 不实现），还需初审者再评估一遍——当前版本此步跳过，设计文档保留章节。
