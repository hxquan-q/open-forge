# AC 白盒测试（流水环节 9）

目标：**全部任务（T）通过评审后**，对**当前项目的完整状态**（不只改动面，没涉及改动的也要评估）做白盒测试。产出白盒测试文档 → 测试子执行 → 结构化问题清单 → 修复循环 → 直到无严重问题。

**执行者**：白盒测试文档由白测子产出（spawn 一次性）；测试执行由白测子完成（可复用会话）；修复走 followup_task 唤醒对应任务的开发子。写域（ac-pipeline §0.3）：`whitebox.md` + `test-results/**` + 项目 `test/` 目录——T2 范围允许档，临时物有界。

## 1. 测试范围（从三处派生）

1. requires.md 验收标准（A# 条目）——逐条要有测试覆盖
2. design.md 测试策略节（白盒重点：调用链验证点）
3. reviews.md 遗留 [一般] 项与各 T 风险记录——重点回归
4. **项目整体健康**（本流水特定：没涉及改动的部分也要纳入评估视野——项目层体检）

## 2. 项目健康总检（先于逐用例，三项必查）

| # | 检查项 | 方法 | 判定 |
|---|--------|------|------|
| P1 | 结构完整性 | 对照 tasks.md：声明的文件全部存在；`git status` 无任务卡外的孤儿文件 | 缺文件/孤儿 → [严重] |
| P2 | 正常启动 | 构建通过 + 项目能起（按项目实际：dev server / 服务进程） | 构建失败/起不来 → [严重] |
| P3 | 已有功能冲突（冒烟） | 挑改动面邻近的**既有**核心功能 2-3 条跑通（回归思维） | 冒烟挂 → [严重] |

规则：体检结果进 whitebox.md 的 P 区；任何 P 项 [严重] → 完成判定必须等 P 项全过；证据要求同机器可判条目（命令输出贴报告，不口头断言）。

## 3. whitebox.md 模板

```markdown
# 白盒测试文档
状态: 草案 | 执行中 | 已执行 | 更新: <时间>
## 1. 测试计划
| # | 用例 | 来源 | 命令/方法 | 判定 |
|---|------|------|-----------|------|
| P1 | 项目健康总检 | §2 | <三条命令> | 三项全过 |
| W1 | <测什么> | A1 | <可执行命令> | <期望> |
## 2. 执行环境
<平台、工具链、测试框架、运行目录>
## 3. 问题清单 schema
severity(严重|一般|轻微)/file/line/test(W#)/message(≤200字符)/stackTail；
verdict: 任一严重→fail；无严重但一般≥3→fail；否则 pass
## 4. 结果（执行后回填）
<用例状态 + 问题清单 + 总结论>
```

用例设计要点：**可执行优先**（能落成命令/测试脚本的不写"人工检查"）；每条注明来源（A#/S#/回归）；启动类用例附运行时长要求（如连续运行 ≥5 分钟无报错）。

## 4. 执行通道（测试子）

1. 测试命令后台跑、输出**落盘**（`--reporter=json --outputFile=<路径>` 或重定向文件）再读——避免管道捕获陷阱。
2. 落盘编码：Windows 下 PowerShell `>` 重定向默认 UTF-16 会误判 binary——用框架自带 outputFile 或 `Out-File -Encoding utf8` 或 node 直接写。
3. 环境级跑不起来（装依赖失败/框架崩）→ 记"待主控处理"，不算测试失败。
4. 问题清单落盘 `docs/ac/test-results/issues-latest.md`（Markdown 表格 + 汇总行），历史轮次存 `issues-round-<n>.md`。
5. 问题状态流转：`待修` → `已修`（复跑通过）/ `未修`（有不能修的理由，待用户裁决）/ `新引入`（下轮重点）。

## 5. 修复循环（主控驱动）

1. 问题清单含任一 [严重]，或 [一般]≥3 → 派修复：
   - 问题可定位到具体任务 → `followup_task(dev_t<n>, ...)` 唤醒该任务开发子（优先，保留其上下文）
   - 跨多任务/无法定位 → 主控评估后指派（新起修复子或最相关开发子）
2. 修复 settlement → 复跑受影响用例 → 更新问题清单（已修/未修/新引入）。
3. **跳回规则**：问题根源在上游产物（需求错了/设计错了）→ 该开发子不得改上游文档，上报主控 → 主控打回对应文档环节（ac-pipeline §5.3）→ 受影响下游作废重走。
4. 循环直至：无 [严重] 且 [一般] 清零或用户接受遗留。修复轮次上限 3 轮，超限上报裁决。
5. 每轮 state.md 更新（executions+1，子环节粒度记录）。

## 6. 完成判定（进黑盒的前置）

- [ ] 项目健康总检 P1/P2/P3 全过（证据在案）
- [ ] 全部 W 用例执行完毕（通过/豁免，豁免有理由）
- [ ] 无未解决 [严重]
- [ ] [一般] 清零或用户书面接受
- [ ] 最终问题清单落盘 + whitebox.md 状态 `已执行`

完成后：state.md 更新（环节 9 done）→ 环节 9 收口（ac-gate 校验）→ 打 stage 档（`stage 9/白盒测试: 全部通过`，含 whitebox.md + test-results/ + 白盒轮修复的代码改动，经轻量 git 子代理 + V4，§0.5）→ 交接 ac-blackbox。
